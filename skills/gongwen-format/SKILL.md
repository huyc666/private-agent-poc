# 公文格式化技能

你的任务：把用户上传的文档（uploads/ 目录）或对话中提供的文稿，整理为规范的党政机关公文（GB/T 9704 风格），**保存为 Word 文档（.docx）交付下载**。

## 工作流程

1. 若用户指明了文档，直接用 read_text_file 读取 `uploads/<文件名>`；未指明时先调用 list_uploaded_docs 查看清单并向用户确认要整理哪份。
2. 从原文提取：标题/事由、主送机关、正文要点、落款单位与日期。原文没有的信息不要编造（缺落款日期可用成文日期占位并注明「请核对」）。
3. 按下面的格式模板整理全文（Markdown 命令风格：`# ` 为标题）。
4. 调用 save_output_file 保存，**必须传 as_docx=true**，文件名以 `.docx` 结尾（建议：`公文-<事由关键词>.docx`，不要与已有输出重名）。转换器会自动套用公文版式（标题居中二号、一级标题黑体、正文仿宋三号、首行缩进 2 字符）。
5. 最终回复：一句话说明整理要点（结构是否完整、哪些字段缺失需用户补充），并**原样附上 save_output_file 返回的下载链接**（/api/files/<文件名>.docx），告知用户点击即可下载 Word 文件。

## 格式模板

```markdown
# <发文机关或事由 + 文种>（如：《关于加强××管理的通知》）

发文字号：<机关代字〔年份〕序号>（原文缺失则省略此行）

<主送机关>：

  <正文开头：缘由/依据。原文有引言则忠实改写>

  <正文主体：分层叙述，用「一、」「二、」一级序号，「（一）（二）」二级，
   保留原文条目顺序与实质内容，仅做格式化与措辞规范化，不增删事实>

  <正文结尾：执行要求或结语（如「特此通知」）>

<div align="right">
<落款单位名称>

<成文日期：××××年×月×日>
</div>
```

## 规则

- 文种判断：告知事项用「通知」，向上汇报用「报告」，答复询问用「函」，请求批准用「请示」；原文明确给出了文种则遵照原文。
- 语言规范：口语转书面语；数字用法按 GB/T 15835（**成文日期用阿拉伯数字**，如「2026年10月9日」，年份全称、月日不编虚位——GB/T 9704-2012）。
- **落款单位与成文日期一律右对齐**：落款单位名称与成文日期两行整体右对齐排版（成文日期位于落款单位正下方、同样右对齐）。生成内容时用 `<div align="right">…</div>` 包裹这两行，并在最终回复说明「落款单位与日期已右对齐」。
- 不新增事实、不改结论；格式项缺失时省略该行，并在回复中提醒用户补充。
- 输出必须是完整可读的公文全文（保存到 Word 文件的内容），对话里只给要点说明 + 下载链接，不重复贴全文。
- **下载链接交付（每次保存后必须）**：每次调用 save_output_file（含修订重存）后的最终回复，必须**原样给出该文件本次返回的下载链接**（形如 /api/files/<文件名>.docx 的纯文本，放在回复末尾）。禁止把链接写成代码块/加反引号装饰；禁止只说「同上」「见之前链接」「拼上访问地址」——修订版也是新保存，必须重新给链接。
- **禁止指导用户拼接 URL**：不要向用户解释相对路径/拼接地址，前端会把链接渲染为可点击下载按钮。
