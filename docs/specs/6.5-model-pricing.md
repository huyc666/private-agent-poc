# Spec — 6.5 模型单价折算（成本金额化）

## 1. 背景与目标

出处：docs/PLAN.md「P6 运营与架构补齐」6.5 行（优先级 4，规模 S，来源 ④ Multica 对标）。

现状：usage_records 只记 token（prompt/completion/total），/api/usage 各聚合视图
（总量 / by_user / by_session / by_run 及 run_usage、session_usage）均无金额，
管理者无法回答「这件事花了多少钱」。目标：配置模型单价后，计量落账时折算金额，
各聚合视图输出金额字段；未配置单价的模型维持仅 token 展示，不影响任何现有链路。
后续 6.2 部门成本报表直接消费本项落库的金额列。

## 2. 需求分析与约束条件澄清

**功能边界**

- 做：模型单价配置（env，输入/输出分开，支持单价 0 对应自建 vLLM 内部核算）；
  落账时折算——usage_records 增 `prompt_cost` / `completion_cost` 金额列（REAL，
  启动时 ALTER 自动迁移老库，幂等）；run_usage / session_usage / summary 各视图
  输出金额汇总字段（prompt_cost / completion_cost / total_cost）；缺单价模型
  cost 记 0、token 照记；非法单价配置显式 WARNING 且对应模型不折算
- 不做：前端金额展示（随 6.2 报表页面交付）；部门维度聚合（6.2 的聚合按部门
  分组时自动带出金额列）；价格历史版本 / 按日期段计价；/api/usage 以外端点；
  MODEL_PRICES 之外的计费维度（如按请求次数计费）

**约束（沿用既有约定）**

- 计量失败绝不阻塞主链路（UsageCallback 既有红线）——折算引入的任何异常同样
  不得影响 record() 落账，单价解析异常按「未配置」处理并 WARNING
- 错误信息不携带原始异常对象与部署路径（警告文案只描述配置问题本身）
- 老库迁移幂等：ALTER 前查表结构，列已存在则跳过（对齐 6.6 的增列迁移模式）
- /api/usage 既有 ACL 不变：user 角色强制只统计本人，金额同样受此约束
- 配置样例同步 .env.example（含单位说明注释）

**待澄清问题（已于 2026-10-17 经用户确认）**

1. 计价单位与币种：**单价按「元/百万 tokens」**（主流厂商报价单口径）。金额字段
   只存数值，单位在 .env.example 注释与文档注明。
2. 价格调整后的历史口径：**历史记录按落账时单价固化**——审计可追溯、重算无歧义，
   单价调整只影响新记录。

## 3. 关键技术与选型决策

| 决策点 | 候选方案 | 选定 | 取舍理由 |
|---|---|---|---|
| 折算时机 | 落账时折算存列 / 查询时按当前配置折算 | 落账时折算（存 prompt_cost/completion_cost） | 聚合 SQL 直接 SUM 即得金额；价格口径清晰（配合待澄清 2 固化）；对齐 6.6 增列迁移模式；查询侧零额外成本 |
| 单价配置载体 | env JSON / 独立 JSON 文件 / STATE_DB 配置表 | env JSON（`MODEL_PRICES`） | PLAN 明示「env 或配置表」二选一；S 规模模型数量少；沿用项目 env 配置惯例，重启生效足够；将来升级文件/表不影响表结构 |
| 缺单价/非法配置行为 | 报错中断 / 静默计 0 / WARNING + 不折算 | WARNING + 不折算（cost=0，token 照记） | PLAN 验收明确「缺单价不报错仅展示 token」；非法配置必须显式暴露——宁可不折算，不折错 |
| 模型名匹配 | 精确匹配 / 精确 + 大小写不敏感回退 | 精确匹配 | 模型名来自提供方元数据（response_metadata.model_name），配置照抄即可；隐式归一化引入歧义 |
| 金额精度 | float 原样 / 落账时定精度 | 落账时 round(x, 6) | 避免 REAL 累加浮点噪声；6 位小数对元级计价足够 |

沿用：usage.py 现有 _ensure_schema / record / _query 链路；tests/conftest.py
离线隔离体系；main.py /api/usage 端点不改动（新字段经 dict 自动透传）。

## 4. 验收标准

| # | 标准（Given/When/Then） | 验证方式 |
|---|---|---|
| AC1 | Given 配置 model-a 输入/输出单价，When 落账一次 model-a 调用（prompt=1000、completion=2000），Then 该行 prompt_cost/completion_cost 为按单价折算值（round 6 位），total_cost = 两者之和 | 单测 |
| AC2 | Given 已配置单价且有落账，When 调用 run_usage / session_usage / summary，Then 各视图每行含 prompt_cost/completion_cost/total_cost 字段，数值等于明细 SUM | 单测 |
| AC3 | Given 未配置单价的 model-b 与已配置的 model-a 混合落账，When 查询各视图，Then model-b 记录 cost 为 0 且 token 正常，total_cost 只含 model-a 部分，全程无报错 | 单测（缺单价路径） |
| AC4 | Given 未配置 MODEL_PRICES，When 正常落账与查询，Then 各视图金额字段为 0，token 统计与现状一致（向后兼容） | 单测 |
| AC5 | Given MODEL_PRICES 为非法 JSON / 负数单价 / 缺字段条目，When 加载并落账，Then 输出 WARNING（文案不含异常原文与路径），对应模型不折算，其余合法条目正常折算，服务不中断 | 单测（非法配置拒绝路径） |
| AC6 | Given 无金额列的老库已存历史 token 记录，When 启动自动迁移，Then 金额列补齐（历史行按 NULL→0 计入汇总）、token 数据不丢，重复启动幂等 | 单测（迁移） |
| AC7 | Given 自建模型单价配置为 0，When 落账，Then 金额为 0 且视为「已配置」（与未配置模型同样仅展示 token，但计入 total_cost 的 0 贡献不报错） | 单测 |

安全/拒绝路径：AC5（非法配置不产生错误金额）；回归确认 /api/usage 既有 ACL
（user 角色只统计本人）在金额字段下不破。
