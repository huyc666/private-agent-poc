# Spec 8.5 · 记忆 LLM 判重

> PLAN 序号 30（M，依赖 8.3）· 目标版本 v0.23.0 · 状态：已确认，待红测试

## 1. 背景与目标

8.3 落地的相似记忆检测基于关键词重叠规则（中文滑动窗口 2-4 字 + 英文单词），
覆盖不了三类场景：

- **同义词/缩写**：「PostgreSQL 是项目数据库」vs「项目用 PG」——关键词无重叠，漏判；
- **语义重复换述**：「我偏好简洁回答」vs「回复请尽量简短」——关键词无重叠，漏判；
- **语义相反误判**：「我喜欢中文」vs「我讨厌中文」——关键词大量重叠，误判为重复。

目标：在关键词规则之上叠加 **LLM 语义判重**——关键词重叠仅作为**前置过滤**
（降成本），候选记忆对送 LLM 做语义裁决，LLM 结果为准。

## 2. 业界对照

- Mem0：向量相似度召回候选 + LLM 判重决定 ADD/UPDATE/DELETE/NONE，两级架构与本方案一致；
- ChatGPT saved memories：写入时由模型判断是否已存在相似条目；
- 共识：LLM 判重正确性远高于规则，但必须控制调用成本（候选预过滤 + 缓存 + 降级）。

## 3. 功能定义

### 3.1 两级判重架构

```
候选对（关键词重叠预过滤）→ LLM 三级裁决 → duplicate / uncertain / distinct
```

- **前置过滤**：沿用 8.3 `_extract_keywords` 关键词重叠规则，仅候选对送 LLM；
  无重叠的从不调用 LLM（成本可控）。
- **LLM 三级裁决**：对每对候选，向模型发起一次轻量判定调用，提示词要求输出
  严格 JSON：`{"verdict": "duplicate" | "uncertain" | "distinct", "reason": "..."}`。
- **处置策略**（按裁决确定性分级）：
  - `duplicate`（确定语义重复）→ **自动合并**，不打扰用户；保留较新条目，
    删除旧条目，审计记录 memory_merge（actor=system，detail 含 merged_from）；
  - `uncertain`（拿不准）→ **交给用户判断**（见 3.2 两个触发点）；
  - `distinct`（确定不重复，如「我喜欢中文」vs「我讨厌中文」）→ 静默，不提示不合并。
- **错误兜底**：LLM 调用失败（超时/解析失败/未配置）→ 按 `uncertain` 处理
  （fail-safe：不确定时交人判断，绝不自动合并），功能不中断，仅打 WARNING 日志。

### 3.2 触发点

1. **save_memory 写入时（对话流，面向 FDE/业务用户）**：
   写入成功后立即对该用户已有记忆执行两级判重——
   - `duplicate`：自动合并（保留新条目），返回消息说明「已与已有记忆 #N 合并」；
   - `uncertain`：返回消息附「检测到与已有记忆 #N 可能重复：<摘要>。
     如需合并请回复『合并』」；**用户在对话中回复合并意图后，模型调用
     `merge_memory` 工具当场执行**，无需跳转控制台；
   - `distinct` / 无候选：正常返回，不附加提示。
2. **控制台合并建议（面向技术人员）**：`renderMergeHints` 改为调用新端点
   `GET /api/memories/similar`（服务端两级判重），**仅展示 `uncertain` 对**
   （`duplicate` 已在写入时自动合并，不重复出现），技术人员一键合并。

### 3.3 merge_memory 工具

新增内置工具 `merge_memory(keep_id: int, merge_from_ids: list[int])`，
复用 8.3 `memories.merge`（权限：仅当前身份本人记忆；审计 actor=当前用户，
区分于自动合并的 actor=system）。供模型在用户对话确认后调用。

### 3.4 成本控制

- 单用户单次检测候选对上限 `MEMORY_LLM_DEDUP_MAX_PAIRS`（默认 10 对，超出截断）；
- LLM 调用使用 `MEMORY_DEDUP_MODEL`（默认复用主模型 `MODEL_NAME`，可配更便宜的小模型）；
- 判定超时 `MEMORY_DEDUP_TIMEOUT`（默认 10s，超时按 distinct 处理并告警）；
- 结果不做跨用户缓存（记忆内容属隐私），仅同进程同内容短期缓存（TTL 5 分钟）。

## 4. 实现要点

- `server/memories.py` 新增：
  - `llm_judge_pair(content_a: str, content_b: str) -> str`：
    返回 `"duplicate"` / `"uncertain"` / `"distinct"`；内部构造 LLM 客户端
    （`ChatOpenAI(model=MEMORY_DEDUP_MODEL, temperature=0)`），
    提示词含正反示例（PostgreSQL vs PG = duplicate；我喜欢中文 vs 我讨厌中文 = distinct）；
    解析失败/超时按 uncertain + WARNING。
  - `find_similar_llm(user_id: str, content: str, category: str) -> dict`：
    关键词候选 → 逐对 LLM 裁决 → 返回 `{"duplicates": [...], "uncertain": [...]}`。
  - `find_similar_pairs_llm(user_id: str | None) -> list[tuple[dict, dict]]`：
    供控制台合并建议端点使用，同用户同分类两两组合，关键词预过滤后 LLM 裁决，
    仅返回 uncertain 对。
- `server/routes/memories.py` 新增 `GET /api/memories/similar`
  （返回 uncertain 相似对列表 `{keep, drop}`，权限同 GET /api/memories）。
- `server/tools_builtin.py`：
  - `save_memory`：写入后调用 `find_similar_llm`（排除刚写入条目）；
    duplicates → 自动 merge（保留新条目）并在返回消息说明；
    uncertain → 返回消息附合并提示（含已有记忆 ID 与内容摘要）。
  - 新增 `merge_memory` 工具并注册到 `tools_admin.py`。
- `web/console.html` `renderMergeHints` 改为 fetch `/api/memories/similar`。
- 测试用 mock 替换 LLM 客户端（不发起真实调用）。

## 5. 验收标准（AC）

| # | 场景 | 验收方法 | 预期 |
|---|---|---|---|
| AC1 | 缩写自动合并 | mock LLM 返回 duplicate：已有「项目数据库是 PostgreSQL」，存「项目用 PG」 | 旧条目自动删除、新条目保留，审计含 memory_merge（actor=system），返回消息说明已合并 |
| AC2 | 语义相反区分 | mock LLM 返回 distinct：「我喜欢中文」vs「我讨厌中文」 | 不合并不提示，两条都保留 |
| AC3 | 无重叠不调 LLM | 「用 Python」vs「公司成立 2010 年」（关键词无重叠） | LLM 客户端零调用，直接返回空 |
| AC4 | LLM 失败按 uncertain | mock LLM 抛异常 | 不自动合并；返回消息附合并提示；WARNING 日志 |
| AC5 | 控制台端点仅 uncertain | GET /api/memories/similar 返回 LLM 裁决为 uncertain 的对；user 只见本人 | 200 + 结构正确 + 隔离；duplicate 对不出现 |
| AC6 | 对话确认合并 | mock LLM 返回 uncertain，save_memory 返回含「回复『合并』」提示；随后调用 merge_memory 工具 | 合并执行成功，旧条目删除，审计 actor=当前用户 |
