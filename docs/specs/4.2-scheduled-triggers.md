## 1. 背景与目标

PLAN 4.2（docs/PLAN.md :50 行）：「定时调度器 + 事件挂钩（如新文件入库触发），执行历史留存」；验收标准「定时流程到点自动执行，历史可查」；依赖 4.1 ✅、规模 M。

4.1 交付了流程固化层：参数化定义、`run_orchestration` 触发入口、`workflow_instances` 实例留存。本项补上自动触发：无需人对话，流程到点或事件发生即自动执行，历史沿用实例表可查且能关联到调度与触发。

## 2. 需求分析与约束条件澄清

### 功能边界

**做**：
- 定时调度：为某个流程定义登记 interval 周期触发，到点自动以登记参数执行
- 事件挂钩：文件上传**且转换成功**后，触发登记了该事件（精确 scope 绑定）的流程定义
- 执行历史：定时/事件触发的实例与手动触发同表留存，可关联调度与触发尝试、可查跳过/拒绝原因
- 调度管理：创建/列举/删除登记 + 查询触发历史（对话式管理工具，与 4.1 工具同风格）

**不做**：
- 不做 cron 语法（仅 interval，评审建议裁决 Q1=A，待确认）
- 不做多进程抢占锁——改为**单进程部署前提 + 启动守护**（见约束，仅文档声明不够）
- 不做错过补跑：停机期间错过的到点不回溯，恢复后按下一轮到点继续（无追赶风暴）
- 不做通用事件总线、不挂 KB 入库（仅文件上传成功，Q4）
- 不做 Web 管理页面（Q5；调度状态/跳过原因必须可经工具查询，避免不可运维）
- 不做在途实例取消：**删除调度只停止未来触发，在途实例自然结束**（契约明确写入 AC）

### 约束

- **后台执行契约（P1-1 修订，纠正原草案事实错误）**：自动实例使用 `session_id=""`、`generation=None`——现有 `check_fence()`（orchestration.py:511-513）对空会话**直接跳过**，自动实例不绑定任何会话删除生命周期、不存在「审批栅栏 aborted」路径；自动执行仍只能装配既有安全工具清单（`FORBIDDEN_TOOL_NAMES` 与 SAFE_* 双层兜底，5.1 既有），危险/审批/管理工具在装配层即拒绝
- **身份时效（P1-2 修订，替换原「永久 Identity 快照」）**：调度行只存创建者**主体**（username）+ 登记时角色/部门（仅审计留痕）；**每次触发时重新解析当前有效身份**（账号存在、未吊销、角色满足 Q3 裁决、部门白名单经包工具权限自然生效）；任一不满足 → 拒绝执行并写**可查询**的触发尝试记录（skipped + 原因），不只记日志；计量归属创建者（触发时身份）
- **事件契约（P1-3 修订）**：登记强制精确 `scope`（上传者域），可选文件名/扩展名过滤；仅在落盘且转换均成功后触发（files.py:175 落盘点之后）；**载荷白名单**：event_id、规范化相对路径（`scope/name`，docx 转换后为 `.docx.md` 名）、上传者主体、scope、字符数、触发时间——不含 preview/全文/绝对路径；上传者域不匹配登记 scope → 不执行；同一上传事件对同一调度幂等（事件 × 调度唯一触发键）；挂钩自带 try/except 完整隔离（外层 except Exception 位于 files.py:184，同步挂钩异常若不隔离会把成功上传变 500——「旁路不阻塞」由挂钩边界 + 测试共同保证）
- **原子防重（P1-4 修订）**：到点判断、claim（租约 + 唯一触发键）与 `next_run` 推进在同一事务（`BEGIN IMMEDIATE` 沿 v0.17.38 写锁先例）；**实例历史不承担锁职责**（`create_instance_row` 本就是 best-effort）；进程崩溃遗留 running → 启动时 stale 清扫：把启动前超龄的 running 实例标 failed（error=「进程重启中断」）；跳过/拒绝均落 `workflow_trigger_attempts` 表
- **部署前提**：仅单进程、每进程仅一个调度循环；进程内守护（同进程二次启动循环拒绝）；启动检测多 worker（uvicorn workers>1）时**拒绝启动调度循环 + WARNING**（fail-closed，防误部署重复执行）
- **异步边界（P2-1 修订）**：`process_due(now)` 是同步函数但**只做 claim 并返回待执行作业**，不在事件循环线程执行编排（`run_orchestration` 是 async，orchestration.py:1087）；循环壳 `asyncio.to_thread` 做 claim、`asyncio.create_task` 派发执行；任务引用集合 + done 回调观察异常；shutdown 取消并等待；重启时在途任务丢失=接受（与不补跑一致，不暗示持久事件队列）
- **可观测（P2-2）**：实例表加 `trigger_source`（manual/scheduled/event）、`schedule_id`、`trigger_id`、`planned_at`（计划触发时间）；`workflow_trigger_attempts` 记录每次触发尝试（触发/跳过/拒绝 + 原因 + 时间）；调度创建/删除/拒绝记审计；interval 契约：首次到点=登记时间+interval、`interval_seconds` 下限 60、长任务跨周期时 claim 中把 next_run 按周期推进到未来（不追赶）、时钟回拨（now < next_run）无动作；登记参数 JSON 的大小/类型/长度限制对齐 4.1 参数上限（单值 2000）
- **多用户隔离**：调度与历史可见性沿用 4.1 口径——user 仅本人、approver/admin 全部；登记入口按 Q3 收口
- **测试可离线跑**：claim/推进核心经注入时钟的同步函数测试，循环只做薄壳，测试零真实等待

### 裁决记录（2026-11-06 用户确认，全按评审建议）

- **Q1 定时语义**：仅 interval——`interval_seconds` 下限 60、首次到点=登记时间+interval、跨周期推进不追赶、时钟回拨无动作；测试注入时钟
- **Q2 管理入口**：仅对话式管理工具（挂 tools_admin），不加端点；工具级 RBAC、资源归属与审计完整（D7/AC9）
- **Q3 建调度权限**：仅 approver/admin 登记（入口收口），**每次触发仍重新鉴权**（P1-2）；删除权限=创建者本人或 admin
- **Q4 事件源**：仅文件上传成功；精确 scope 绑定 + 白名单载荷 + 幂等键
- **Q5 页面**：纯后端+工具；跳过/失效原因必须可经工具查询（AC4）

## 4. 验收标准

- **AC1 调度登记与管理**（单测）：登记成功落表可查（含 scope 绑定、参数摘要、interval、创建者、next_run）；interval 下限/非法参数/定义不存在或校验失败/登记参数不合法（`_resolve_trigger_params` 拒绝）/scope 缺失均拒绝且文案明确；删除后不再触发且留审计；**删除只停未来触发，在途实例自然结束**
- **AC2 定时触发**（单测，注入时钟）：到点自动执行——实例行含 `trigger_source=scheduled`/`schedule_id`/`trigger_id`/`planned_at`，终局正确；未到点不触发；首次到点=登记时间+interval
- **AC3 事件触发**（单测）：上传且转换成功后触发登记匹配的执行并留痕（docx 转换后 `.docx.md` 路径正确入载荷）；无登记/上传者域不匹配/过滤不中/失败上传（含 docx 转换失败）均不触发；载荷仅白名单字段（无 preview/全文/绝对路径）；同一事件重复派发对同一调度幂等
- **AC4 历史与原因可查**（单测）：`list_workflow_instances` 可见自动实例（可见性同 4.1）；触发历史工具可查每次尝试（触发/跳过/拒绝 + 原因 + 时间）——**跳过/失效不只存在日志**
- **AC5 原子防重**（单测）：同一到点并发两次 claim 只执行一次；事件与 interval 同时到同一调度不重复；**实例写库失败不破坏互斥**（锁在调度行不在实例行）
- **AC6 身份时效**（单测）：登记后吊销/删除/降级角色不满足 Q3/调岗后部门权限不满足 → 下一次触发拒绝并留痕（`workflow_trigger_attempts`）；计量归属创建者；恢复有效身份后按下一轮到点恢复执行
- **AC7 执行边界 fail-closed**（单测）：自动实例 `session_id=""`/`generation=None` 不绑会话生命周期（无栅栏 aborted 路径）；危险/审批/登记类工具在装配层被拒；定义已删除/改参致登记失效 → 留痕跳过不崩溃；循环单轮异常继续运行
- **AC8 重启恢复**（单测）：登记持久化——新连接重读仍在；启动 stale 清扫把超龄 running 实例标 failed（「进程重启中断」）；不补跑错过的到点
- **AC9 权限与工具边界**（单测）：登记类工具进 `FORBIDDEN_TOOL_NAMES`（编排定义引用被拒）；user 角色登记被拒（Q3=A）；删除权限=创建者本人或 admin（approver 不能删他人登记）；创建/删除/拒绝有审计
- **AC10 推进与幂等**（单测，注入时钟）：长任务跨多个周期时 next_run 推进到未来、不追赶；时钟回拨（now < next_run）无动作；`interval_seconds` 生产下限 60 不受测试注入影响
- **AC11 旁路与生命周期**（单测）：挂钩同步异常/派发异步异常均不影响上传响应（上传仍 200）；服务退出取消并等待在途任务、无未观察异常（done 回调）；重启在途任务丢失=接受（与不补跑一致）
- **AC12 部署守护**（单测）：同进程二次启动调度循环被拒；多 worker 配置下调度循环拒绝启动 + WARNING
- **AC13 回归与覆盖**（回归）：全量用例通过、18 skipped 语义不变、新代码覆盖率 ≥90%
