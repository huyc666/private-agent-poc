# Spec — 8.1 用户记忆沉淀与召回

状态：**草稿待确认**
流程档位：PLAN 功能（M）；裁剪：无（新增数据表 + API 端点 + 控制台页面，带页面触发加严流程）
spec 独立评审：**触发**（新增数据表/存储机制，跨 ≥3 个顶层模块）
出处：`docs/PLAN.md`（P8 记忆管理，优先级 26，M，验收「用户 A 在第一会话说『记住我偏好中文回复』，第二会话开场模型即知；记忆条目可在页面查看与管理」）
依赖：6.4 已交付 SQLite/Postgres 双后端统一适配（`server/db.py`）

## 1. 背景与目标

当前「上下文滚动压缩」（v0.17.7）只解决**单会话**超窗口问题：窗口外旧消息滚动为摘要，但摘要仅存在于当前会话的进程内缓存（`_compact_cache`），重启即失、跨会话不可见。

本项补「**跨会话持久记忆**」：用户偏好、项目事实等可复用资产沉淀到 STATE_DB，新会话开场时自动召回注入系统提示，实现「用户 A 在第一会话说『记住我偏好中文回复』，第二会话开场模型即知」。

目标版本：v0.20.0（新增数据表 + API 响应结构 + 控制台页面）

## 2. 需求分析与约束条件澄清

### 2.0 业界方案调研（2026-11-22）

对照三大开源记忆框架与两大商业产品，提炼可复用模式：

| 方案 | 架构 | 核心机制 | 对本项启发 |
|---|---|---|---|
| **Mem0** | 记忆层框架（外挂） | LLM 从每轮对话提取事实 → 向量+图混合存储 → 相似度召回 | 自动提取是噪音源（误提取）；本轮先用显式指令，8.3 再做自动提取 |
| **Letta (MemGPT)** | Agent 运行时（内置） | 分层记忆（core/archival）+ Agent 自主编辑（工具调用） | 记忆即工具调用（save_memory）符合 agent 自主性；但本轮不做分层，简化为一层 |
| **Zep (Graphiti)** | 时序知识图谱 | 事实带有效期、可supersede；图数据库存关系 | 过期机制必要（Q4）；图数据库过重，本轮用关系表即可 |
| **ChatGPT (OpenAI)** | 商业产品 | 两阶段：saved memories（显式指令，2024-04）→ dreaming（后台自动提取+chat history 引用，2025-04） | 显式指令是 MVP 基线；「dreaming」自动提取是增强（8.3）；项目管理页签必要（Q3） |
| **Claude (Anthropic)** | 商业产品 | 项目级记忆隔离 + 用户可查看/编辑 + Invisible Chat（不留痕） | 按用户隔离是基础（AC5）；项目级隔离过重（本轮按用户即可）；用户可控（查看/编辑/删除）必须 |

**共识**：
- **显式指令是基线**：ChatGPT saved memories / Claude 手动编辑均支持；自动提取是增强（噪音大）
- **用户可控是底线**：查看/编辑/删除必须（ChatGPT/Claude 均提供管理页）
- **按用户隔离是基础**：Claude 项目级隔离是增强（本轮不做）；Invisible Chat 是隐私兜底（本轮用「禁用记忆」开关覆盖）
- **过期机制必要**：Zep 时序图、ChatGPT「记忆可能过时」均提示；默认 90 天合理

### 2.1 功能边界

- **记忆存储**：新增 `user_memories` 表（`id / user_id / content / category / created / updated / expires_at / enabled`），SQLite/Postgres 双后端统一适配。
- **记忆写入**：对话中自动提取（模型识别用户偏好/事实性陈述）+ 用户显式指令（「记住…」）两种途径；每条记忆带分类标签（preference/fact/project/context）。
- **记忆召回**：新会话开场时，按当前用户 ID 查询启用记忆，筛选相关条目注入系统提示；注入量控制（默认 ≤2000 tokens，不挤压上下文窗口）。
- **记忆管理**：控制台新增「记忆管理」页签——列表查看/编辑/删除/启用禁用/过期设置；admin 可查看全量（管理需要），user 只看本人。
- **记忆隔离**：严格按用户隔离，bob 无法看到 alice 的记忆；开放模式（AUTH_ENABLED=false）记忆归属 anonymous 用户。
- **明确不做**：
  - 不做记忆向量化检索（本轮用关键词匹配 + 最近更新时间排序）
  - 不做记忆自动合并/去重（8.3 范围）
  - 不做记忆版本历史（只保留最新版本）
  - 不做记忆导入导出（备份恢复由 STATE_DB 层面保障）
  - 不改 v0.17.7 会话内压缩机制（两者正交：压缩管单会话窗口，记忆管跨会话持久）

### 2.2 约束

- **写入不阻塞**：记忆提取失败时只记日志、不影响对话主链路（与审计/计量失败处理一致）。
- **隐私保护**：记忆内容可含用户偏好等敏感信息，存储时按用户隔离；审计只记操作（谁/何时/增删改），不记记忆内容本身。
- **性能**：记忆注入在每轮模型调用前执行一次（随 `_dynamic_prompt`），查询必须命中索引（user_id + enabled），单次查询 <10ms。
- **注入量控制**：默认上限 2000 tokens，超出时按 `updated` 倒序截断；可通过环境变量 `MEMORY_MAX_TOKENS` 调整。
- **数据库兼容**：新表需同时兼容 SQLite 与 Postgres；DDL 幂等（`CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ADD COLUMN IF NOT EXISTS`）；Postgres 时间戳用 `DOUBLE PRECISION`（与 6.4 口径一致）。
- **依赖**：不新增 Python 依赖（复用现有 FastAPI/Pydantic/psycopg）。

### 2.3 待澄清问题

**Q1 记忆提取触发时机**（参考 ChatGPT 两阶段演进）：
- 方案 A：每轮模型回复后异步提取（后台任务，不阻塞响应）
- 方案 B：用户显式说「记住」时才写入（保守，零误提取，对齐 ChatGPT saved memories）
- 方案 C：每 N 轮（如 10 轮）批量提取一次

建议 **B 起步**（ChatGPT 2024-04 初版即此模式；Mem0 自动提取噪音大，需 LLM 判重/合并，复杂度高）；A 对齐 ChatGPT dreaming（2025-04 增强版），作为 8.3 智能管理增强。是否同意？

**Q2 记忆召回相关性判断**（参考 Mem0 vs ChatGPT）：
- 方案 A：全量注入（用户记忆少时可行，ChatGPT saved memories 初版即全量）
- 方案 B：关键词匹配当前用户输入，只注入相关条目（Mem0 向量检索降级版）
- 方案 C：向量相似度检索（Mem0 核心机制，需 embedding 模型，内网断网场景需本地方案）

建议 **A + 注入量控制**（≤2000 tokens，对齐 ChatGPT 初版）；B 作为 8.3 增强；C 明确不做（内网部署需本地 embedding，且与 2.1 RAG 的向量检索职责重叠）。是否同意？

**Q3 记忆页面入口**（参考 ChatGPT/Claude）：
- 方案 A：console.html 新增「记忆管理」页签（与审计/用户管理并列，对齐 Claude 项目级记忆页）
- 方案 B：独立页面 /memory.html

建议 **A**（与 6.3 审计页签同模式；ChatGPT/Claude 均在设置页提供记忆管理入口）。是否同意？

**Q4 记忆过期机制**（参考 Zep 时序图 vs ChatGPT「记忆可能过时」提示）：
- 方案 A：不过期，用户手动删除
- 方案 B：默认 90 天过期，可配置（对齐 Zep 事实有效期）
- 方案 C：按记忆类型区分（preference 永不过期，context 默认 7 天，对齐 Zep 不同时效性）

建议 **B**（统一 90 天，简化管理；ChatGPT 通过「记忆可能过时」提示用户更新，而非自动过期；8.3 再做差异化）。是否同意？

| D4 | 召回注入点 | A. `_dynamic_prompt`；B. `_pre_model_hook` | **A**。与领域包片段/专属技能索引同层注入，统一系统提示组装逻辑 |

### 3.1 数据模型

```sql
CREATE TABLE IF NOT EXISTS user_memories (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  -- Postgres: BIGINT GENERATED BY DEFAULT AS IDENTITY
    user_id TEXT NOT NULL,                  -- 关联 api_users.username
    content TEXT NOT NULL,                  -- 记忆内容（明文，敏感信息由用户自行判断）
    category TEXT NOT NULL DEFAULT 'fact',  -- preference / fact / project / context
    created DOUBLE PRECISION NOT NULL,      -- epoch 秒
    updated DOUBLE PRECISION NOT NULL,      -- epoch 秒（编辑/召回时更新）
    expires_at DOUBLE PRECISION,            -- epoch 秒，NULL = 永不过期
    enabled INTEGER NOT NULL DEFAULT 1      -- 0/1，禁用后不召回但保留
);
CREATE INDEX IF NOT EXISTS idx_user_memories_user_enabled
    ON user_memories(user_id, enabled);
```

### 3.2 API 端点

- `GET /api/memories` — 列表查询（user 只看本人，admin 可看全量；过滤参数 category/enabled）
- `POST /api/memories` — 创建记忆（用户自助写入「记住…」）
- `PATCH /api/memories/{id}` — 编辑记忆（内容/分类/启用/过期时间）
- `DELETE /api/memories/{id}` — 删除记忆（硬删除，不进回收站）

权限：user 只能操作本人记忆；admin 可操作全量；approver 与 user 同口径（不开放管理权限）；开放模式归属 anonymous。

### 3.3 记忆召回流程

1. `_dynamic_prompt` 组装系统提示时，调用 `memories.get_active_memories(user_id, limit_tokens=2000)`
2. 查询 `user_memories` 表，过滤 `user_id=? AND enabled=1 AND (expires_at IS NULL OR expires_at > now)`
3. 按 `updated DESC` 排序，逐条累加 token 数，超限时截断
4. 格式化为独立段落注入：

```
---

用户记忆（{count} 条）：
{for each memory}
- [{category}] {content}
{endfor}
```

5. 每次召回后更新 `updated` 字段（LRU 语义，活跃记忆排在前面）

### 3.4 记忆写入流程（方案 B：显式指令）

1. 用户说「记住我喜欢中文回复」
2. 模型识别「记住」关键词，调用工具 `save_memory(content, category)`
3. 工具调用 `memories.create(user_id, content, category)` 写入 STATE_DB
4. 写入成功返回「已记住」；失败只记日志、返回「记忆写入失败，不影响本次对话」

工具定义（新增 `save_memory`）：
- name: `save_memory`
- description: 保存用户偏好、项目事实等长期记忆，供后续会话召回使用
- args: `content: str, category: str = "fact"`
- 权限：user/approver/admin 均可调用（写本人记忆）；开放模式归属 anonymous

### 3.5 审计集成

复用 6.3 审计框架，新增 action 类型：
- `memory_create`：创建记忆（target = memory_id）
- `memory_update`：编辑记忆（target = memory_id，detail = 修改字段列表）
- `memory_delete`：删除记忆（target = memory_id）

不记记忆内容本身（隐私保护）。

### AC 明细

**AC1 schema**：Given 新部署或老库，When 启动应用，Then `user_memories` 表幂等创建（SQLite + Postgres 双后端），索引 `idx_user_memories_user_enabled` 存在。

**AC2 显式写入**：Given 用户 alice 在对话中说「记住我喜欢中文回复」，When 模型调用 `save_memory` 工具，Then `user_memories` 表新增一行（user_id=alice, content=我喜欢中文回复, category=fact）。

**AC3 召回注入**：Given alice 有 2 条启用记忆，When 新会话开场组装系统提示，Then 系统提示含「用户记忆（2 条）」段落，列出两条记忆内容。

**AC4 注入量控制**：Given alice 有 50 条记忆（总 token 数 5000），When 召回时 `MEMORY_MAX_TOKENS=2000`，Then 只注入最近更新的若干条（累计 ≤2000 tokens），并在段落末尾标注「（共 50 条，仅显示最近 N 条）」。

**AC5 权限隔离**：Given alice 和 bob 各有记忆，When alice 调 `GET /api/memories`，Then 只返回 alice 的记忆；When admin 调同一端点，Then 返回全量记忆。

**AC6 CRUD API**：Given alice 登录，When 调 `POST /api/memories` 创建记忆，Then 返回 201 + memory_id；When 调 `PATCH /api/memories/{id}` 编辑，Then 返回 200；When 调 `DELETE /api/memories/{id}`，Then 返回 204 且记录删除。

**AC7 审计集成**：Given alice 创建/编辑/删除记忆，When 操作完成，Then `audit_log` 表各有对应记录（action=memory_create/update/delete, actor=alice, target=memory_id），detail 不含记忆内容。

**AC8 过期过滤**：Given alice 有 3 条记忆（1 条已过期、2 条未过期），When 召回时，Then 只注入 2 条未过期记忆；过期记忆仍在表中但不召回。

**AC9 页面验收**：Given admin 登录控制台，When 打开「记忆管理」页签，Then 可见记忆列表（含用户/内容/分类/更新时间/启用状态）；When 编辑某条记忆，Then 保存后列表刷新；When alice 在第一会话创建记忆、第二会话开场，Then 模型回复中体现记忆内容（留证截图）。
