# PLAN 8.4：admin 跨会话操作通知

**规模**：S  
**依赖**：3.1（会话所有权模型）  
**来源**：⑤（用户新增需求——隐私合规增强）

## 1. 需求背景

admin 角色保留全局会话视图（管理职责，v0.17.37 设计意图），但用户指出这违反隐私最小化原则。8.4 补充隐私合规增强：**admin 查看/介入他人会话时，系统向会话归属用户发送通知**。

业界先例：
- GitHub：管理员访问私有仓库时，仓库所有者可看到审计日志
- AWS CloudTrail：所有管理操作记录审计，用户可查询
- 企业微信/钉钉：管理员查看员工会话需审批并通知员工

## 2. 功能范围

### 2.1 通知触发点
- admin 打开他人会话（GET /api/sessions/{id}）
- admin 在他人会话中发送消息（POST /api/chat）

### 2.2 通知形式
- **会话内通知**：用户下次打开该会话时，顶部显示横幅「管理员 {username} 于 {timestamp} 查看了此会话」
- **通知持久化**：记录到 session_notifications 表，用户可标记已读
- **审计日志**：复用 6.3 审计框架（action=admin_view_session / admin_intervene_session）

### 2.3 通知内容
- 管理员用户名
- 操作类型（查看/介入）
- 操作时间
- 会话 ID（短格式，前 8 位）

### 2.4 通知展示
- 未读通知：会话顶部横幅（黄色背景）
- 已读通知：不再显示（用户点击「知道了」标记已读）
- 多条通知：显示最新一条，括号标注「等 N 条」

## 3. 技术方案

### 3.1 数据模型

```sql
CREATE TABLE IF NOT EXISTS session_notifications (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL,
    owner_id TEXT NOT NULL,          -- 会话归属用户
    admin_id TEXT NOT NULL,          -- 操作管理员
    action TEXT NOT NULL,            -- view / intervene
    created_at REAL NOT NULL,        -- 操作时间戳
    read_at REAL,                    -- 已读时间戳（NULL=未读）
    INDEX idx_owner_unread (owner_id, read_at)
);
```

### 3.3 通知查询

```python
# server/routes/sessions.py
@router.get("/{session_id}/notifications")
async def get_session_notifications(request: Request, session_id: str):
    """查询会话未读通知（仅归属用户可见）。"""
    identity = request.state.user
    meta = sessions.get_meta(session_id)
    if not meta or meta["owner_id"] != identity["username"]:
        raise HTTPException(403, "仅会话归属用户可见")
    
    return notifications.list_unread(session_id, identity["username"])

@router.post("/{session_id}/notifications/{notification_id}/read")
async def mark_notification_read(request: Request, session_id: str,
                                  notification_id: int):
    """标记通知已读。"""
    identity = request.state.user
    ok = notifications.mark_read(notification_id, identity["username"])
    if not ok:
        raise HTTPException(404, "通知不存在或无权限")
    return {"ok": True}
```

### 3.4 前端展示

```javascript
// web/index.html（会话页面）
async function loadSessionNotifications(sessionId) {
  const { ok, data } = await api(`/api/sessions/${sessionId}/notifications`);
  if (!ok || !data.length) return;
  
  const latest = data[0];
  const banner = document.createElement('div');
  banner.className = 'admin-notification-banner';
  banner.innerHTML = `
    ⚠️ 管理员 ${esc(latest.admin_id)} 于 ${fmtTime(latest.created_at)}
    ${latest.action === 'view' ? '查看' : '介入'}了此会话
    ${data.length > 1 ? `（等 ${data.length} 条）` : ''}
    <button onclick="markNotificationRead(${latest.id})">知道了</button>
  `;
  document.querySelector('.chat-header').after(banner);
}
```

## 4. 验收标准（AC）

| AC | 类型 | 验收方法 | 状态 |
|----|------|----------|------|
| AC1 | 单测 | `test_ac1_admin_view_creates_notification` | ⏳ |
| AC2 | 单测 | `test_ac2_notification_persistence_and_query` | ⏳ |
| AC3 | 单测 | `test_ac3_mark_notification_read` | ⏳ |
| AC4 | 单测 | `test_ac4_admin_intervene_creates_notification` | ⏳ |
| AC5 | 单测 | `test_ac5_audit_log_admin_view_session` | ⏳ |
| AC6 | 页面人工验收 | admin 查看 alice 会话，alice 登录看到横幅通知 | ⏳ |

**AC1 查看通知**：Given admin 查看 alice 的会话，When 查询 session_notifications 表，Then 有一条记录（owner_id=alice, admin_id=admin, action=view, read_at=NULL）。

**AC2 通知持久化与查询**：Given alice 有未读通知，When alice 调用 GET /api/sessions/{id}/notifications，Then 返回未读通知列表（按时间倒序）。

**AC3 标记已读**：Given alice 有未读通知 ID=1，When alice 调用 POST /api/sessions/{id}/notifications/1/read，Then read_at 更新为当前时间，再次查询不再返回。

**AC4 介入通知**：Given admin 在 alice 会话中发送消息，When 查询 session_notifications 表，Then 有一条记录（action=intervene）。

**AC5 审计日志**：Given admin 查看 alice 会话，When 查询审计日志，Then 有一条记录（actor=admin, action=admin_view_session, target=alice）。

**AC6 页面验收**：Given admin 查看了 alice 的会话 S1，When alice 下次打开会话 S1，Then 顶部显示黄色横幅「管理员 admin 于 2026-11-22 14:30 查看了此会话」，点击「知道了」后横幅消失。

## 5. 隐私与安全

- **最小化通知**：仅记录 admin 操作，普通用户互访不记录（避免噪音）
- **不可抵赖**：通知记录不可删除（仅可标记已读）
- **审计分离**：通知表与审计表分离（通知面向用户，审计面向合规）
- **会话隔离**：通知仅归属用户可见，其他用户（含其他 admin）不可见
