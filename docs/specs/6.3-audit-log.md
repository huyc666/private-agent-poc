# PLAN 6.3 — 统一操作审计日志（spec）

> 版本：2026-10-26 · 状态：待用户确认
> 定位：P6 运营与架构补齐 · 序号 12 · 规模 M · 纯后端 + 控制台页签（带页面功能，走加严流程）

## 一、背景与目标

当前敏感操作散落三处、口径不一：

| 操作 | 现状 |
|---|---|
| 管理动作（建用户/轮换/吊销等七端点） | 仅 `[admin]` print 到 stdout（v0.17.29），服务重启即失 |
| 审批决议 | approvals 表只存决议结果，无独立审计流水 |
| 登录 / 文件读写 | 完全无记录（login_fails 仅记失败计数） |

目标：新建 `audit_log` 表统一落库（独立于 Langfuse 观测——观测服务可断连/清空，审计须本地持久），admin 可按 who / when / what 查询并导出 CSV，满足「任一敏感操作可查」的合规底线（PLAN 6.3 验收标准）。

## 二、需求分析与约束澄清（请确认）

**审计范围**（写入点）：

| # | 事件 | 记录内容 | 备注 |
|---|---|---|---|
| A1 | 登录成功 | actor、来源 IP | pat- 令牌发放 |
| A2 | 登录失败 | 尝试的用户名、IP | 与 login_fails 计数互补，记流水 |
| A3 | 管理动作 ×7 | 延续 `_audit` 现有 action/target 口径 | 打印改为落库（保留 print） |
| A4 | 审批决议 | 批准/驳回、审批单 ID、决议人 | |
| A5 | 文件上传 / 删除 / 技能包导入 | 文件名（域内相对路径） | 写操作必记 |
| A6 | 文件下载（/api/files、kb 原文定位） | 文件名 | **读操作**：建议记录——下载是数据外流主通道 |
| A7 | 内置工具的文件写 / 删（do_write/do_delete） | 工具级写路径 | 工具级「读」**不记**（每轮对话多次，噪音大于价值）|

**待确认问题**：
1. **Q1 页面形态**：审计查询收口到 console.html 新增「审计日志」页签（admin 专属，含条件过滤 + CSV 导出）。→ 本项因此属**带页面功能**，spec 确认后先出页面原型（trae-design:solo-design）经你审核再进 TDD。是否同意？
2. **Q2 A6 读记录**：文件下载记审计（如上）；若你觉得噪音大可降为仅记 kb 原文定位。
3. **Q3 保留策略**：容量上限 10 万条，超限裁最旧 10%（对齐 login_fails 10k 上限先例），单机 SQLite 不做归档。同意？
4. **Q4 查询权限**：仅 admin 可查/导出（approver 不可看他人操作流水，与会话隐私收紧口径一致）。同意？

**硬约束**（沿项目既有约定）：
- 审计写入失败**不阻塞主链路**（与计量失败处理一致：log warning 继续）
- 明文密码 / Key 值绝不入审计（target 只存用户名/文件名/审批单 ID）
- 目标文件名存**域内相对路径**，不含服务器绝对路径
- STATE_DB 单机多进程共享；Postgres 化随 6.4 演进（本项只做 SQLite）
- 错误信息不带原始异常对象（防绝对路径泄露）

## 三、关键技术与选型决策

- **新模块 `server/audit.py`**：`log(actor, role, action, target, detail)` + `query(...)` + `export_csv()`；表 `audit_log(id, ts, actor, role, action, target, detail)`，ts 用毫秒整数（与 usage_records 口径一致）
- **落库位置**：STATE_DB（跨进程可见，登录/管理/文件操作同源）；启动时 CREATE TABLE IF NOT EXISTS + 容量裁剪（复用 login_fails 裁剪模式）
- **接入方式**：`main._audit` 改为调 audit.log（七端点零改动语义）；登录在 auth.login 成功/失败处各加一行；审批在 approval.resolve 加一行；文件端点与 do_write/do_delete 各加一行——均为**单行调用**，不动业务逻辑
- **查询端点**：`GET /api/audit`（admin 专属，过滤参数 actor/action/since/limit≤1000）+ `GET /api/audit/export`（CSV 流式下载）；拒绝路径：未登录 401、非 admin 403、开放模式 400（复用 `_admin_guard`）
- **页面**：console.html 新增「审计日志」页签——过滤器（操作人/动作/时间）+ 表格 + 导出按钮；tokens.css 既有组件复用，无新视觉体系
- **测试**：新增 `tests/test_audit.py`（每事件类型 1 条 + 拒绝路径 + 容量裁剪 + 写入失败不阻塞），预计 15~18 个用例

## 四、验收标准

- **AC1** 登录成功与失败均可在审计表查到 who/when/what（含 IP）
- **AC2** 七个管理动作各操作一次，审计表可查到对应 action/target
- **AC3** 批准一次审批后，审计表含决议人与决议结果
- **AC4** 上传、删除、技能包导入、下载各一次，审计表有完整流水（相对路径，无绝对路径）
- **AC5** admin 在控制台审计页签可按操作人/动作过滤查询并导出 CSV；user/approver 调 /api/audit 返回 403，开放模式 400
- **AC6** 审计超 10 万条触发裁旧；写入异常（如表锁死）不阻塞登录/上传等主流程
- **AC7** 全量回归通过；审计记录中不出现明文密码、Key 明文与服务器绝对路径
