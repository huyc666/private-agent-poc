## 1. 背景与目标

当前 14 张业务表分散在 `STATE_DB`（SQLite）与 `USAGE_DB`（SQLite），WAL +
busy_timeout 只支持同机多进程，不满足跨机多副本共享状态的前置条件。6.4 将这些
表与相应读写路径切换到 PostgreSQL，保持单进程默认部署可用，同时提供
`STATE_BACKEND=postgres`、`USAGE_BACKEND=postgres` 下的跨进程/跨副本共享能力。

目标版本：v0.18.0（引入部署形态变化；README 只写功能，技术细节落本 spec）

## 2. 需求分析与约束条件澄清

### 2.1 功能边界

- 配置：新增 `STATE_BACKEND`（`sqlite`/`postgres`）、`USAGE_BACKEND`
  （`sqlite`/`postgres`），默认 `sqlite`；Postgres 模式分别复用
  `STATE_DATABASE_URL`、`USAGE_DATABASE_URL`，未设置时回退 `DATABASE_URL`。
- 数据面：完整覆盖 `STATE_DB` 12 张表（`messages`、`session_meta`、
  `approvals`、`api_users`、`auth_tokens`、`login_fails`、`audit_log`、
  `session_locks`、`workflow_instances`、`workflow_schedules`、
  `workflow_trigger_attempts`、`disabled_packs`）与 `USAGE_DB` 2 张表
  （`usage_records`、`run_records`）。
- 兼容：SQLite 默认路径、既有 API 响应字段、测试隔离体系、登录/审计/审批/
  调度行为不变；Postgres 模式为新增部署选项，不删除 SQLite。
- 迁移：只支持 SQLite → PostgreSQL 的一次性显式迁移，迁移前必须显式备份；
  不做反向迁移，不覆盖既有 PostgreSQL 目标表。

### 2.2 数据类型与约束

- 时间戳：`created`、`ts`、`expires_at`、`started_at`、`next_run` 等现用
  epoch-seconds 的 REAL/INTEGER 列，Postgres DDL 固定映射为
  `DOUBLE PRECISION NOT NULL`（不使用 `TIMESTAMPTZ`，保证 AC1 零往返误差）；
  `audit_log.ts`（毫秒）映射 `BIGINT NOT NULL`。
- 金额：`prompt_cost`、`completion_cost` 映射 `DOUBLE PRECISION NOT NULL`，
  不用 `REAL`/`float4`（避免 6.8 评审 P2-3 的 ulp≈128s 类精度退化）。
- 字符串：保持 `TEXT`；主键/唯一键不变；`INTEGER`（布尔/计数）按语义分别
  映射 `SMALLINT`/`INTEGER`/`BIGINT`（`revoked`、`generation` 为 INTEGER）。
- 数据完整性：Postgres 外键不作为本轮新增约束，避免迁移老数据因历史兼容
  NULL/孤儿行失败；表级主键、唯一索引、普通索引必须等价保留。
- 6.8 P2-3：Postgres `by_run` SQL 必须避免 `GROUP BY u.run_id` + 裸列
  `u.session_id`、`u.user_id`、`u.date` 的非法组合；实现需重写为合法
  GROUP BY/聚合表达式。
- 6.8 P2-6：Postgres DDL/迁移清单必须显式包含 `run_records`（主键、列、
  `run_id` 对齐 `usage_records.run_id`），防止迁移漏表。

### 2.3 并发/事务约束

- 会话代际栅栏、审批创建栅栏、注册抢注、调度 claim/lease、事件唯一键等
  check-then-write 操作必须保持跨进程原子。
- SQLite `BEGIN IMMEDIATE`/`INSERT OR IGNORE` 语义在 Postgres 模式下分别
  转为显式事务、`ON CONFLICT DO NOTHING/UPDATE` 或等价单语句原子更新；
  不得把 check-then-write 拆到两个事务。
- `session_locks.acquire` 优先用单条 `INSERT ... ON CONFLICT ... WHERE`
  原子语句；若实现保持三步事务，则必须用行锁/`SELECT ... FOR UPDATE` 并发
  测试证明无跨副本双持有。
- 审计写入失败仍按旁路原则吞异常打类型名，不阻塞主链路；packs 启停写失败
  仍保持安全方向可见失败。

### 2.4 部署与测试约束

- 不新增依赖：复用 `psycopg[binary,pool]>=3.1` 与
  `langgraph-checkpoint-postgres>=3.1.3`；requirements 无变更，无需 pip-audit 增量。
- Postgres 16 为目标；schema 建表幂等；连接失败 fail-fast，不静默回退 SQLite。
- Windows 开发机可跑本地 PG 单元/集成测试；async checkpointer 既有 Windows
  Proactor 限制不变，Docker 双进程验收不受影响。
- 测试默认仍用临时 SQLite；新增 Postgres 测试走 `RUN_PG_TESTS=1` 或复用
  `RUN_DOCKER_TESTS=1` 门控，不得污染本地真实库。

### 2.5 待澄清问题

无：配置口径与默认行为已由 PLAN 与既有 `DATABASE_URL`/Docker 先例约束，可按
本方案进入评审；评审若提出变更，回写后再请求确认。

## 3. 关键技术与选型决策

| # | 决策点 | 方案 | 理由 |
|---|---|---|---|
| D1 | 迁移/DDL 工具 | 引入 SQL migration 模块，代码内执行幂等 DDL；不引入 Alembic | 现状无迁移框架；14 张表需可控变更；POC 取舍基线允许轻量方案；避免新依赖与 pip-audit 变更 |
| D2 | Postgres 连接 | `psycopg` 连接池，同步调用为主；复用既有依赖 | 当前各模块均为同步函数；服务端已有 `asyncio.to_thread` 边界；最小侵入 |
| D3 | schema 抽象 | 各业务模块保持公共函数不变，内部按 backend 分派；不建立全局 ORM | 行为等价、可测试性最好；ORM 重构会扩大风险面且超出 M 规模 |
| D4 | SQLite 迁移 | 一次性 CLI 导出 SQLite 表→Postgres 目标库，先建 schema 后每 500 行分批 copy，主键唯一冲突 fail-fast；`messages`、`audit_log`、`usage_records` 的 identity 序列在显式 id 导入后执行 `setval(pg_get_serial_sequence(...), COALESCE(MAX(id),0)+1, false)` | 明确、可审计；迁移是部署动作，非运行时自动转换；sequence 重同步覆盖空表与历史表，避免下一次插入撞显式导入 id |
| D5 | 表存储归属 | `STATE_*` 与 `USAGE_*` 可指向不同 PG database；也可用两个 schema/同一 database | 兼容现有 STATE_DB/USAGE_DB 分离部署；迁移工具必须支持显式目标 URL |
| D6 | by_run P2-3 修法 | SQL 中 `session_id/user_id/date` 改为 `MAX(...)` 等聚合或补全 GROUP BY | 保持 SQLite 结果不变，同时满足 PG 语法；不改变现有接口 |
| D7 | run_records P2-6 | `run_records` 单独列入 DDL 与迁移清单，并加入 schema 完整性测试 | 防止 6.8 评审指出的漏表问题 |

### AC 明细

**AC1（P2-3）**：Given Postgres schema 已建，When 执行 `summary().by_run`
多模型调用/多 run 聚合，Then SQL 不报 `column ... must appear in GROUP BY`
错误，`session_id/user_id/date/status/wall_ms` 与 SQLite 等价；时间/金额列
迁移后往返误差为 0。

**AC2（P2-6）**：Given Postgres schema 已建，When 查询 `information_schema`，
Then `run_records` 存在且包含 `run_id PRIMARY KEY, user_id, session_id,
started_at, finished_at, wall_ms, status, created_at`；`run_records.run_id`
与 `usage_records.run_id` 值可对齐。

**AC3**：Given 两客户端并发对同一 Postgres 会话执行 `append_fenced`/删除，
Then 仅代际匹配且未删除的一方写入成功，另一方 fail-closed 拒绝。

**AC4**：Given A 进程创建审批、B 进程查询/决议，Then B 可见 A 的 pending
审批，且仅一次 pending→approved/rejected 转换成功。

**AC5**：Given Docker PG + 两个应用进程指向同一 Postgres，When A 进程创建会话
并写入消息/创建审批，B 进程读取会话并处理审批，Then 消息/审批互通，端点无
回退 SQLite 写入。

**AC6**：Given 默认 `STATE_BACKEND=sqlite`、`USAGE_BACKEND=sqlite`，When 执行
既有全量测试，Then 通过率不低于基线（约 1202 passed / 20 skipped）且行为不变。

**AC7**：Given Postgres schema 已建，When 读取表/索引清单，Then 与 §2.1 的
14 张表完全一致，且测试逐张断言表名，无缺表；索引名/语义等价保留。

**AC8**：Given 构造含上述 14 张表、P2-3 精度样本的 SQLite 库，When 执行显式
迁移，Then Postgres 行数一致、主键/唯一键约束保留、时间戳与金额值一致、
自增主键下一次插入不撞历史 id，目标库已有同名表时失败且不覆盖。

**AC9**：Given Postgres 配置不可达，When 初始化状态/用量模块，Then fail-fast
报告连接失败，不得静默回退 SQLite；连接错误不写入日志中的敏感 URL。

**AC10**：Given Postgres 模式下审计/计量写入异常，When 登录/对话主链路继续，
Then 仅日志出现异常类型名，主链路不被阻塞。

**AC11**：Given 并发 `register_session` 与 `session_locks.acquire`，Then 会话
注册恰一人成功，锁同一时刻仅一持有者；过期租约可被接管。

**AC12**：Given 并发 `process_due` claim 与事件触发，Then 每个到点/事件仅一
claim 成功，trigger attempt 唯一键冲突幂等。

## 7. 收敛结论

### 7.1 实现收敛

- **统一适配层**：新增 `server/db.py`，`STATE_BACKEND`/`USAGE_BACKEND`
  默认 `sqlite`；显式 `postgres` 时经 `STATE_DATABASE_URL`/
  `USAGE_DATABASE_URL` 或 `DATABASE_URL` 连接 PostgreSQL，连接失败
  fail-fast，不回退 SQLite，不暴露 URL/raw exception。
- **Schema / 迁移**：`PG_DDL` 覆盖 14 张表与既有索引语义；epoch/金额列
  使用 `DOUBLE PRECISION`，审计毫秒时间戳使用 `BIGINT`，不新增外键。
  `tools/migrate_db.py` 提供一次性双源迁移，先备份 SQLite、创建幂等 PG
  schema、拒绝非空目标，再复制 14 表并重置 identity 序列。
- **业务模块**：`sessions/approval/auth/audit/session_lock/packs/
  orchestration/schedulers/usage` 均经 `db.connect`；PG 跳过 SQLite
  PRAGMA/DDL；`BEGIN IMMEDIATE`/`INSERT OR IGNORE`/`INSERT OR REPLACE`
  分别翻译为显式事务、`ON CONFLICT DO NOTHING` 与 PG upsert。
- **P2-3**：`usage.summary().by_run` 的非分组列改为
  `MAX(u.session_id/user_id/date)`，消除 PG 非法裸列；DDL 使用
  `DOUBLE PRECISION` 防止 float4 精度退化。
- **P2-6**：`run_records` 纳入 `PG_TABLES`、`PG_DDL` 与迁移复制清单。
- **跨进程语义**：适配层用 psycopg 连接池（默认 `autocommit=False`）；
  `BEGIN IMMEDIATE` 翻译为 `SELECT 1`，保留 psycopg 隐式事务，使行锁与
  后续写入处于同一事务。会话/审批栅栏用 `SELECT ... FOR UPDATE`；会话租约
  改为单语句 `INSERT ... ON CONFLICT ... WHERE` 原子接管；登录限流与
  调度定义级租约用 `pg_advisory_xact_lock` 串行化；到点调度用
  `FOR UPDATE SKIP LOCKED`；触发留痕用唯一键 + `cursor.rowcount` 保持
  exactly-once。
