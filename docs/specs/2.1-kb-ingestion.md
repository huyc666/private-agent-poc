# Spec — 2.1 文档入库管道（多格式解析 + BM25/向量混合检索）

## 1. 背景与目标

PLAN.md P2 首项（优先级 7，规模 L）：v0.17.0 已有 BM25 检索参考实现
（`tools/build_kb.py` 建索引 + `packs/core-knowledge`/`kb-demo` 包内自包含检索工具，
中文 bigram 分块、SQLite 单文件、来源标注）。本项补齐两个缺口：

1. **解析扩展**：当前仅 .md/.txt，补 Word/PDF/Excel/PPT/网页五类格式入库；
2. **语义检索**：本地 embedding（内网断网可用）与 BM25 混合排序，语义问法
   （非关键词直配）也能命中。

做完的样子：`python tools/build_kb.py kb/hr` 一条命令，目录内各类文档统一解析、
分块、双通道索引；Agent 检索工具返回混合排序后带来源标注的条文；全程离线可用。

## 2. 需求分析与约束条件澄清

### 功能边界
- **做**：.docx/.pdf/.xlsx/.pptx/.html/.htm 解析为结构化文本后复用现有
  中文分块；.md/.txt 保持现状；向量通道（本地 embedding）+ BM25 双通道索引；
  RRF 混合排序；core-knowledge 与 kb-demo 两个包检索工具升级为混合检索版。
- **不做**：.doc/.xls/.ppt 老二进制格式（需 LibreOffice/Tika 级重依赖，
  明确报错提示转存为新格式）；扫描件 PDF（无文本层，跳过并 WARNING）；
  OCR；增量索引（维持重跑全量重建，更新即生效归 2.3）；管理界面（归 3.x）；
  faiss/向量数据库（数据量 POC 级，SQLite + numpy 暴力检索足够）。

### 约束（受既有约定影响）
- **包工具自包含**（PACK_GUIDE）：检索工具不 import server 任何模块；
  升级后需 `tools/sign_pack.py` 重新签名（签名随内容失效是预期行为）。
- **计量红线同款兜底思想**：单文档解析失败不得阻塞整个索引构建——
  try/except 跳过 + WARNING 列明失败清单。
- **解析上限**：单文件解析大小上限 50MB（防畸形大文件拖垮内存，
  超限跳过 + WARNING，与 docx 解压 20MB 上限同一防御思路）。
- **零网络调用**：embedding 引擎与模型本地加载，索引与查询全链路无网络请求。
- **离线安装**：新依赖必须是纯 pip 离线可装（预置 wheel），不接受需编译
  系统库或 JVM 的方案。

### 待澄清问题（已全部答复，2026-10-17 用户确认）
1. **embedding 引擎** → 选 **A. fastembed**（ONNX + bge-small-zh-v1.5，总量
   ~150MB，无 torch）。代码以 EMBED_BACKEND 配置化隔离引擎：`local`（默认，
   fastembed 进程内推理，保证断网验收）/ `openai`（外部 OpenAI 兼容
   /v1/embeddings 服务，用户确认可调用外部服务时按需配置）。
2. **embedding 模型** → BAAI/bge-small-zh-v1.5（512 维）；内网无现成
   embedding 服务，外部服务走 openai 后端配置。
3. **扫描件 PDF** → 按 spec 处理：跳过 + WARNING。
4. **老格式 .doc/.xls/.ppt** → 按 spec 处理：明确报错提示转存 OOXML。

## 3. 关键技术与选型决策

| 决策点 | 候选 | 选定 | 理由 |
|---|---|---|---|
| 文档解析 | Apache Tika（JVM）/ unstructured（重）/ 纯 Python 分库 | **分格式选轻量纯 Python 库**：docx=python-docx、pdf=pypdf、xlsx=openpyxl、pptx=python-pptx、html=stdlib HTMLParser | 全部离线 pip 可装、零系统依赖，与项目「零重型依赖」取向一致（docx 生成即手写 OOXML） |
| 解析输出统一 | 每格式自定义分块 | **统一转伪 Markdown（标题行+段落），复用 chunk_markdown** | 索引期一套分块逻辑；docx 按 Heading 样式、html 按 h1-h4、pptx/xlsx 按页/Sheet 作章节、pdf 每页作章节兜底 |
| 向量引擎 | fastembed / sentence-transformers / 外部服务 | **EMBED_BACKEND 配置化**：默认 `local`（fastembed + bge-small-zh-v1.5，进程内离线推理）；可选 `openai`（外部 OpenAI 兼容 /v1/embeddings）。小接口隔离，引擎可替换 | 用户 2026-10-17 确认 A：断网全链路可复是硬验收，fastembed 体积负担最小 |
| 向量存储 | faiss / 独立向量库 / SQLite | **SQLite chunks 表加 vec BLOB 列（float32）**，查询侧 numpy 点积暴力检索 | 千级块 × 512 维 ≈ 2MB 内存，沿用单文件零新组件 |
| 混合排序 | 加权线性 / RRF | **RRF（k=60）**：BM25 top20 + 向量 top20 融合 | 无需调权、对两通道分数量纲不敏感、业界标准 |
| 管道形态 | 新工具 / 扩展现有 | **扩展 tools/build_kb.py**（命令与参数不变），解析器独立 `tools/kb_parsers.py`（索引期专用，不进包） | 保持「一条命令建索引」；包工具自包含约束只作用于查询侧 |
| 查询侧 | 平台统一检索服务 / 包内自包含 | **沿用包内自包含模板**，升级两个检索工具（内嵌分词+BM25+向量+RRF，引擎进程内缓存） | 不破坏 PACK_GUIDE 约束与既有包模式 |

## 4. 验收标准

| # | 验收标准 | 验证方式 |
|---|---|---|
| AC1 | 五类新格式样例（docx/pdf/xlsx/pptx/html）入库后 chunks 表均有内容，heading 含章节/页信息 | 单测（测试内程序化生成最小样例文件） |
| AC2 | .md/.txt 索引与检索行为不回退（bigram 分块、BM25、来源标注与 v0.17.0 一致） | 既有用例保持绿 + 回归 |
| AC3 | 每块 embedding 落库且维度一致；查询向量化点积排序正确（注入确定性假向量验证管道） | 单测（假向量，离线确定性） |
| AC4 | RRF 融合结果符合公式预期；单通道无结果时自动退化为另一通道 | 单测 |
| AC5 | 语义问法（非关键词直配，如「入职多久能休年假」）命中语义相关条文 | 门控集成测（RUN_EMBED_TESTS，真模型，需模型文件） |
| AC6 | 拒绝路径：.doc 等不支持格式明确报错；损坏文件单文档跳过 + WARNING，其余文档索引不受阻 | 单测 |
| AC7 | 全链路零网络调用：引擎/模型本地加载，索引与查询不发起网络请求 | 单测断言加载路径 + 门控环境实测 |
| AC8 | 升级后的两个包检索工具源码不含 `import server`（自包含）；重新签名后加载为可信 | 单测（源码静态断言）+ 手工验证 |
