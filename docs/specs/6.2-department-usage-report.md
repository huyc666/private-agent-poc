# Spec — 6.2 部门成本报表

## 1. 背景与目标

出处：docs/PLAN.md「P6 运营与架构补齐」6.2 行（优先级 5，规模 S，来源 ②）。

现状：v0.17.20（6.5）后用量明细已带金额，但聚合视图只有 总量/按用户/按会话/按
任务 四个维度，管理者无法回答「每个部门花了多少钱」；6.1 已给 api_users 加了
department 字段。目标：新增按部门聚合的用量视图（含 6.5 金额列）与 CSV 导出
端点，部门成本报表可落成文件交付。

## 2. 需求分析与约束条件澄清

**功能边界**

- 做：
  - 用量聚合新增「按部门」视图（`by_department`）：每个部门的调用次数、token
    三列、金额三列（prompt_cost/completion_cost/total_cost，来自 6.5 落账列）
  - CSV 导出端点：按部门报表下载（UTF-8 带 BOM，Excel 直接打开不乱码），文件名
    含日期范围；CSV 列含部门与全部聚合指标
  - 查询参数沿用 /api/usage 惯例（days 过滤最近 N 天）
- 不做：
  - 前端报表页面（已确认：随批次三 3.x 管理控制台交付）
  - 部门维度写回 usage_records（落账结构不动，已确认查询时按当前映射）
  - 多币种、税率、预算阈值告警

**约束（沿用既有约定）**

- ACL 沿用 /api/usage 语义：user 角色看不到部门报表（部门是管理视角，user 强制
  只统计本人，无部门维度可言）——部门视图与 CSV 端点仅 approver/admin 可用；
  开放模式（无身份）沿用现有端点的全局可见行为
- 跨库现实：usage.db 与 state.db 是两个 SQLite 库，无法 SQL join——部门映射由
  auth 层提供，Python 侧聚合（见选型 1）
- 无部门用户（未设置部门、SSO 未透传、开放模式匿名标识）归入「未分配」分组，
  不丢数据
- 错误信息不携带原始异常与部署路径；CSV 由服务端生成，文件名不含服务器路径
- 计量红线：报表是只读查询，任何查询异常不得影响计量落账主链路

**待澄清问题（已于 2026-10-17 经用户确认，均按推荐）**

1. 交付边界：本次仅交付 **CSV 导出 + API 视图**，报表页面随批次三 3.x 管理控制台。
2. 部门口径：按 api_users **当前映射**查询时聚合（调岗即时反映、usage 表零改动）。

## 3. 关键技术与选型决策

| 决策点 | 候选方案 | 选定 | 取舍理由 |
|---|---|---|---|
| 部门映射时机 | 查询时按 api_users 当前映射 / 落账时快照写入 usage_records | 查询时映射（Python 侧聚合） | 待澄清 2；S 规模免改 schema，用户量级（百级）Python 聚合无性能压力；usage.py 不反向依赖 auth（main.py 注入映射），保持模块边界 |
| CSV 生成 | Python stdlib csv / pandas | stdlib csv + io.StringIO | 报表列固定、无计算需求，不值得引入重依赖；项目零 pandas |
| CSV 编码 | UTF-8 / UTF-8 带 BOM | UTF-8 带 BOM（utf-8-sig） | 目标用户用 Excel 打开，无 BOM 中文必乱码 |
| 端点形态 | 复用 /api/usage 加 format 参数 / 独立 /api/usage/departments(.csv) | 独立 GET /api/usage/departments 与 /api/usage/departments.csv | 职责单一；CSV 响应头（Content-Disposition）与 JSON 混在一个端点语义混乱；按部门聚合的映射逻辑独立成函数便于测试 |
| 视图落点 | usage.summary() 增 by_department / 独立 department_usage() | 独立 usage.department_usage(days, department_map) | summary 的四个视图均为纯 SQL 单库查询，by_department 需要外部映射注入，混入会破坏 summary 的调用契约 |

沿用：/api/usage 的 _acl_identity ACL 模式；usage._query 只读查询链路；
tests/conftest.py 离线隔离体系（usage 独立 tmp 库 + auth 独立 state 库）。

## 4. 验收标准

| # | 标准（Given/When/Then） | 验证方式 |
|---|---|---|
| AC1 | Given 三个用户分属两个部门（含一个无部门用户）且各有已折算落账，When 查询 by_department 视图，Then 每部门一行含 calls/token 三列/金额三列，数值等于该部门成员明细之和；无部门用户计入「未分配」行 | 单测 |
| AC2 | Given days=1 参数，When 查询，Then 只统计最近 1 天记录（与 /api/usage days 语义一致） | 单测 |
| AC3 | Given 部门 A 两个成员，When 导出 CSV，Then 响应为带 BOM 的 UTF-8 文本，表头含部门与全部聚合指标列，数据行与视图一致，Content-Disposition 为 attachment 且文件名含日期 | 单测 |
| AC4 | Given user 角色身份，When 请求部门视图 JSON 与 CSV 端点，Then 均 403（拒绝路径：部门是管理视角，user 无权）；approver/admin/open 模式正常返回 | 单测（ACL） |
| AC5 | Given 部门成员的落账金额为 0（缺单价模型，6.5 行为），When 查询部门视图，Then 该部门金额列正常输出 0，token 统计不受影响（视图层不做二次折算） | 单测（边界） |
| AC6 | Given 空库（无任何落账），When 查询视图与 CSV，Then 返回空列表/仅表头，不报错 | 单测（边界） |

安全/拒绝路径：AC4（user 角色越权访问部门报表 403）；CSV 文件名由服务端固定
模式生成（无用户输入拼接，无路径注入面）。
