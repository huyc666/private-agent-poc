# Spec — 3.1 用户与 Key 管理（管理控制台首项）

出处：docs/PLAN.md 执行序号 11（规模 M，P3 管理控制台首项，依赖无）。

## 1. 背景与目标

用户与 Key 的全生命周期管理目前只有 CLI（tools/manage_users.py：
add / rotate / passwd / setdept / revoke / list），非技术运营人员无法操作；
服务端管理端点为零（仅 /api/auth/login、/api/auth/logout）。PLAN P3 定位
「交给非技术人员运营」，本项是控制台首个落地页。

目标：admin 专属 Web 管理控制台（独立页面 console.html），把 CLI 六项能力
收口到页面并补齐「设角色」（CLI 无此命令，角色只能建用户时一次定死），
实现用户全生命周期管理：列表查看、建用户（一次性 Key）、轮换 Key、
重置密码、设角色、设部门、吊销账号。CLI 保留作脚本化场景。
验收口径（PLAN）：admin 页面完成全生命周期操作，user/approver 无此入口。

## 2. 需求分析与约束条件澄清

### 功能边界

- **用户列表**：用户名 / 角色 / 部门 / 状态（正常、已过期、已吊销）/
  密码是否已设置 / Key 过期时间 / 创建时间，口径与 CLI list 一致
  （auth.list_users 现成数据，含 has_password）。
- **建用户**：用户名 + 角色 + 部门（可选）+ Key 有效期天数（0=永不过期）
  → 弹窗展示一次性明文 pak- Key（仅此一次）+ 复制按钮；同名、保留名
  shared、非法角色、超长用户名被拒（复用 add_user 既有校验）。
- **轮换 Key**：二次确认 → 展示新一次性 Key，旧 Key 立即失效
  （rotate_user 现成）。
- **重置密码**：输入新密码（≥MIN_PASSWORD_LEN=8 位）或一键生成随机密码
  （set_password 现成）。
- **设角色**：user / approver / admin 三选一（**新增 auth.set_role**，
  本次唯一的新业务函数）。
- **设部门**：建用户时与列表行内编辑均可，空串清除（set_department 现成）。
- **吊销账号**：二次确认，立即生效，不可逆（**不支持解禁**，澄清答复 4）；
  被吊销者 pak- Key 与 pat- 登录令牌立即 401（revoke_user 现成）。
- **入口可见性**：仅 admin 登录后 header 出现「控制台」入口；user/approver
  不渲染；开放模式不渲染（无用户体系）。

### 约束（沿用既有约定）

- **双层拦截**（与包级 RBAC 同构）：前端隐藏入口只是体验层；
  /api/admin/* 在服务端判定 request.state.user.role == "admin"，
  user/approver → 403，未认证 → 401（中间件既有），开放模式 → 400
  （与 login 端点对开放模式的处理一致）。
- **明文 Key 只出现一次**：API 响应返回后不落库不缓存，前端不写入
  任何持久存储；服务端日志不得打印明文 Key。
- **自我保护**：admin 不能吊销自己、不能把自己的角色改为非 admin
  （后端拒绝）——CLI 无此约束，页面化后误操作风险高，防「最后一个
  管理员自锁」。
- **错误提示**不携带服务器内部路径与异常对象（项目惯例）。
- **审计**：本次仅结构化服务日志（who/what/target，澄清答复 3）；
  统一审计表随 6.3（执行序号 12，紧随本项）。
- **前端零外部依赖**：全部样式与脚本内联或本地文件，断网内网可用。

### 待澄清问题（已获用户答复，2026-10-22）

1. **页面形态** → **独立页面 console.html**：管理操作是表格+表单形态，
   与聊天界面差异大；避免 index.html 继续膨胀；3.2 包与审批面板
   复用同一控制台框架。
2. **tokens.css 拆分** → **本次拆出**（v0.17.28 已预留「随 3.1 做」）。
3. **审计** → **仅服务日志**，审计表由 6.3 统一落库。
4. **吊销恢复** → **不支持**，与 CLI 对齐；误吊销换用户名重建。

## 3. 关键技术与选型决策

| 决策点 | 候选 | 选定 | 理由 |
|---|---|---|---|
| 页面形态 | ① 独立 console.html ② 聊天页内嵌面板 | **① 独立页面**（用户答复） | 表格+表单与聊天形态差异大；index.html 已 1100+ 行；3.2 复用框架 |
| 后端复用 | ① 复用 auth.py 函数+薄端点 ② 端点内重写 SQL | **① 薄端点** | add_user/rotate_user/set_password/set_department/revoke_user/list_users 全部现成且 CLI 已验证；仅新增 set_role（与 set_department 同构）；业务规则单处维护 |
| admin 守卫 | ① 每端点手写判断 ② FastAPI 依赖注入统一挂载 | **② 依赖注入 require_admin** | 一处实现七端点复用；漏挂即测试拒绝路径兜底 |
| 端点设计 | ① 单端点 + action 参数 ② 逐动作端点 | **② 逐动作端点**（GET /api/admin/users；POST …/rotate、…/password、…/role、…/department、…/revoke；POST /api/admin/users 建用户） | 动作语义清晰、审计日志天然按端点区分；单端点 action 分发易漏鉴权 |
| tokens.css | ① 拆出共享文件 ② 控制台复制变量 | **① 拆出 web/tokens.css**（用户答复） | 两页面共享同一 token 源，避免漂移；本地文件不违反断网可用；经受限白名单静态路由提供（参照 /vendor 既有模式，不做任意路径文件服务） |
| .btn 组件 | ① 本次建组件+改造 index.html 全部按钮 ② 组件随 tokens.css 建立，仅控制台使用 | **② 仅控制台使用** | index.html 按钮 v0.17.28 已达标，改造是纯回归风险零收益；组件化收敛放 3.2/后续 |
| 确认交互 | ① 原生 confirm() ② 自定义确认模态 | **② 自定义模态** | 吊销/轮换是不可逆敏感操作，需明确后果描述；复用登录遮罩与审批卡既有样式语言 |
| 测试落点 | ① 扩展既有测试文件 ② 新建 tests/test_admin_users.py | **② 新建文件** | 独立功能域，避免文件膨胀；test_acN_* 命名；放行+拒绝路径成对覆盖（安全防线惯例：拒绝路径专门补用例） |

## 4. 验收标准

- **AC1 入口可见性**：admin 登录 → header 出现「控制台」入口且可进入；
  user / approver 无入口；开放模式无入口。
- **AC2 用户列表**：admin 打开控制台可见全部用户（用户名/角色/部门/状态/
  密码已设/Key 过期/创建时间），状态判定（正常/已过期/已吊销）与 CLI
  list 口径一致。
- **AC3 建用户**：admin 建用户成功 → 弹窗展示一次性明文 Key，刷新或重开
  页面后不可再取；新 Key 可登录；同名、保留名 shared、非法参数被拒并
  给出友好提示。
- **AC4 轮换 Key**：admin 轮换成功 → 新 Key 可用，旧 Key 立即 401。
- **AC5 重置密码**：≥8 位设置成功且被重置用户可用新密码登录；<8 位被拒；
  一键生成的随机密码满足长度要求。
- **AC6 设角色**：admin 修改用户角色后立即生效（角色实时查表）；admin
  不能把自己的角色改为非 admin；非法角色值被拒。
- **AC7 设部门**：admin 修改部门后立即生效（部门报表聚合与知识库分库
  权限按新部门过滤）；空串清除部门。
- **AC8 吊销**：admin 吊销用户 → 该用户 pak- Key 与 pat- 令牌立即 401，
  列表状态变「已吊销」；无恢复途径；admin 不能吊销自己。
- **AC9 权限拒绝路径**：user / approver 直连 /api/admin/* → 403；未携带
  凭据 → 401；开放模式 → 400；拒绝响应不泄露内部信息。
- **AC10 审计日志**：每个管理动作产生结构化服务日志（操作者/动作/目标
  用户），日志不含明文 Key。
- **AC11 tokens.css 拆分回归**：index.html 与 console.html 共享
  web/tokens.css；index.html 视觉与 v0.17.28 无肉眼可见差异（人工确认）。
- **AC12 全量回归**：既有测试全部通过；新增测试覆盖 AC1~AC9 的放行与
  拒绝路径（离线，mock 凭据/临时 STATE_DB）。

验证方式：AC2~AC9、AC12 单测/集成测（离线）；AC1、AC11 页面演示 +
人工测试确认；AC10 日志抽查。
