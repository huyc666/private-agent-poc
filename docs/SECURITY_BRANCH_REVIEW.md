# 安全分支覆盖审查报告 · Private Agent POC v0.17.17

审查范围：server/ 安全相关模块（auth / approval / state / tools_builtin / custom_tools / skills / packs / config / main / telemetry / usage）
审查日期：2026-10-14
对应变更：v0.17.16 → v0.17.17（commit 8952d63，新增 tests/test_deny_paths.py）

## 总体结论

行覆盖视角下测试体系已达标（86%），但分支覆盖审查发现 **测试全部打在各安全防线的「放行侧」，拒绝侧基本裸奔**——共 10 项高风险缺口，全部为安全防线的拒绝分支从未被任何用例执行。

本轮新增 32 个离线用例逐个补齐，全量 346 个离线用例通过、无回归。安全模块分支覆盖显著提升（approval 100%、auth 98%、tools_builtin 95%），总体分支覆盖 84.2%（875/1124）。无阻断性缺陷，防线代码本身未发现问题，属测试债而非代码缺陷。

## 1. 审查方法

1. 离线全量 `pytest --cov=server --cov=sandbox --cov-branch --cov-report=json`
2. 解析 coverage JSON，按「行覆盖 vs 分支覆盖」对比排序安全模块
3. 对每个缺失分支（arc 起点→终点）对照源码逐个评估：可达性、安全语义、风险等级
4. 可离线触达的拒绝分支全部补用例；不可达/无安全语义的明确记录不补理由

行覆盖的盲区在于：一行 `if` 只要测过 True 分支即计满，False 分支（拒绝/失败路径）可能从未执行——而防线的价值恰恰在拒绝侧。

## 5. 审查中确认的正确行为（无需改代码）

- `AUTH_PROXY_ALLOWED_IPS` 含一个非法 token → 整个白名单弃用（fail-closed），符合安全默认
- 上传端点的穿越分支是纵深防御：`_upload_safe_name` 前置过滤后仅剩符号链接竞态可达，同类拒绝语义已在下载/删除端点实测
- 限流表容量清理与失败登录自身记账语义兼容，锁定中的条目不会被误清

## 6. 后续建议

1. **分支覆盖纳入回归指标**：回归命令追加 `--cov-branch`，防止新增防线只测放行侧（本轮缺口即由此漏检）
2. **SSO 端到端用例**：当前依赖测试环境 monkeypatch 白名单；若 SSO 上生产，建议增加一条经受信代理转发身份头的端到端用例
3. **main.py 剩余缺口维持不补决策**：SSE 租约恢复路径属运行时故障恢复，离线构造成本高且已有多进程真实运行背书
