### 2.1 N1：M1 的修复把「汉字后单字母 + 冒号」变成了误报

M1 把前边界从「`^` 或非 `\w`」改成「前一个字符不是 `[A-Za-z0-9_]`」，方向是对的：
`读取/etc/passwd并执行`、`打开C:foo`、`见~/secret`、UNC 四种紧邻写法现在都能拦住
（`tests/test_workflow_drafting.py:486-497`，本轮实测通过）。问题在于驱动字母分支
`[A-Za-z]:` 只需要「一个 ASCII 字母 + 冒号」，而新的前边界把汉字视为边界，于是
中文正文里最常见的中英混排列表项被当成盘符：

```
"方案A: 采用两级审批"   → 旧正则 False，新正则 True  → validate_definition 拒绝
"选项C: 说明"           → 旧正则 False，新正则 True  → 拒绝
"型号A: 200"            → 旧正则 False，新正则 True  → 拒绝
"role a: 负责"          → 旧正则 False，新正则 True  → 拒绝
```

已用当前代码实测：`validate_definition` 对上述描述返回
`['定义文本包含绝对路径（已拒绝，错误信息不回显原路径）']`。这不是理论风险：
中文业务文档的「方案A/选项B/步骤C」是高频写法，一旦被模型抄进角色 prompt 或定义
description，生成与手工导入都会被误拒。

建议修法（三者取一，优先前两条）：
1. 收紧驱动字母分支的后边界，例如 `[A-Za-z]:(?=[A-Za-z0-9._~\\/])`，
   既保留 `C:foo`，又不命中 `A: 说明` / `A：`；
2. 把驱动字母分支改为 `[A-Za-z]:[\\/]`，放弃无斜杠 `C:foo` 的覆盖，用其他形态兜底；
3. 至少给 `A:` 增加常见盘符白名单（`C:`–`Z:`）并保留后边界，但单字母型号仍可能撞上，
   不如前两条彻底。

同时补一条负向用例（正常中文列表项不被判为绝对路径），避免只测「能拦」不测「不误拦」。
