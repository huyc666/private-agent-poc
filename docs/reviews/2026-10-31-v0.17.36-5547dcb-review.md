## 1. 复验结论

上轮 R7～R9 三项问题均通过代码逐行复核与独立行为复现：

- 包内目录链接（`skills/x -> ../hidden`）在解析期被严格布局规则拒收，签名/热检测/索引/加载四集合恢复同一。
- 加载期 TOCTOU 换链不再能返回包外内容：包来源技能索引/加载只读接受时物化的快照，准入后无第二次磁盘读取。
- 包根链接循环（注入式与真 junction 自环）不再中断扫描与热检测，异常包 fail-closed，哨兵差异驱动重扫，恢复后自愈重新 signed。

R5、附属文件纯重命名、恢复 mtime 篡改检测、未声明兄弟过滤、frontmatter 别名兼容等既有修复均无回归。本轮复验范围内未发现新的阻断项，**v0.17.36 可作为本轮领域包信任链整改的安全基线**。

验证范围声明：本轮独立行为复现在 Windows 本机以 junction 形态真跑；POSIX 真符号链接形态因本机无创建权限未独立执行，其代码路径与 junction 经同一 `resolve()` 检查同构，且项目 AC1/AC3 用例在支持环境恒跑。交叉审查子代理本轮因额度中断未完成，结论以主审本人逐行复核 + 独立复现为准，未声称双子代理交叉验证。真实模型主链路、多副本部署仍不在本报告已验证范围内。

## 2. R7：包内目录链接严格布局拒收，已通过

`server/packs.py::_resolve_in_pack` 在包根包含校验之后追加技能目录必须解析到 `<pack>/skills` 树内的校验，junction 与 POSIX symlink 经 `resolve()` 穿透后同形拒绝。`sign_pack_files` 仍可正常签出包本体（链接目标不再进可挂载集合）。

独立复现（junction 真跑，`skills/x -> ../hidden` 含 `hidden/SKILL.md`，同包正常声明 y）：

```text
r7_link_skill_rejected=True        # skills==[y]，x 解析期拒收
r7_pack_still_signed=True          # trust=signed, status=ok
r7_blindspot_not_indexed=True      # hidden 的 frontmatter 名不入索引
r7_none_loadable_via_link=True     # x/hidden/blind-spot 三个名字均不可加载
r7_y_loadable=True
```

拒收时打印「技能目录解析后不在 skills 树内」告警，可定位。签名盲区（POSIX rglob 不跟随目录符号链接导致链接目标内容不进 HMAC）由此从源头消除——不是把盲区纳入签名，而是禁止该布局进入挂载集合，与 spec 选择的严格方案一致。

## 3. R8：加载快照闭合 TOCTOU，已通过

`_parse_pack` 在技能四重校验接受瞬间单次读取 `SKILL.md` 存入 `skill_texts`（键 = 解析后真实路径，避免同 basename 嵌套别名串包），经 `register_pack_skills` → `register_extra_dir(texts=...)` 传递；`list_skills` / `load_skill` 直查与 frontmatter 兜底三个服务入口对包来源一律取快照，准入通过后不再读盘。检测入口（`skills.signature`、`packs.packs_signature`）维持读盘，磁盘变化必反映为签名变化并驱动重建整体替换快照。

独立复现（hook `_skill_entry_ok` 在准入通过瞬间把技能目录换成指向包外的 junction）：

```text
r8_swap_happened_in_window=True    # 换链确实发生在检查-读取窗口内
r8_no_outside_content_direct=True  # 直查返回快照「包内已验内容」，非包外内容
r8_no_outside_content_index=True   # 索引描述同样不泄露包外内容
r8_signature_detects_swap=True     # 检测层捕获换链
```

另补一个变体：换链指向**包内** `tools/`（root 校验可通过但出 skills 树），加载仍只返回快照，包内替换内容不可达：

```text
r8_inpack_link_returns_snapshot=True
```

正常技能、frontmatter 别名技能在快照机制下均可正常加载（回归见第 5 节）。

## 4. R9：链接循环按包/按来源收口，已通过

`scan_packs` 每包捕获 `(OSError, RuntimeError)` 转 error 态条目；`packs_signature` 每包捕获生成 `__error__:<类型>` 哨兵条目；`skills.signature` 每来源捕获生成带来源标签的哨兵；`packsign.verify` 捕获范围扩展 RuntimeError，compute 生成路径维持严格上抛。

独立复现（注入 `Path.resolve` 对特定包抛 `RuntimeError: Symlink loop`，未设签名密钥以保证解析走到技能分支）：

```text
boom_error_state=True    # 异常包 error 态，错误信息含 Symlink loop
calm_ok=True             # 健康包 status=ok
sentinel=True            # 热检测条目为哨兵，不上抛
calm_normal=True         # 健康包条目正常
heal_boom_ok=True        # resolve 恢复后失效缓存重扫，包回 ok
```

真 junction 自环（包目录 rmtree 后 `mklink /J d d`）：

```text
r9_selfloop_junction_created=True
r9_selfloop_detected_no_raise=True   # packs_signature 不上抛且条目变化
r9_selfloop_healthy_intact=True      # 健康包继续参与
r9_self_heal_resigned=True           # 恢复真实目录重签后 trust=signed
```

热重载接线核实：`agent.py::_maybe_reload`（L255-258）比较 `packs_signature()/skills.signature()` 差异后调 `_rebuild_graph`，后者先 `invalidate_scan_cache()`（L81）重扫重验，再 `reset_extra_dirs + register_pack_skills`（L105-106）整体替换快照——哨兵差异确实能驱动自愈，不会缓存永久可信的异常状态。

注：首轮复现脚本有两处断言失败均为脚本自身问题（先填充了扫描缓存导致不重扫；设置签名密钥使未签名包在签名校验处提前短路返回 unavailable），修正后全部通过，非代码缺陷。
