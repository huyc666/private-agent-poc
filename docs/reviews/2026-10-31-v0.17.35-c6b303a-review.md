## 1. 复验结论

v0.17.35 对上轮常规攻击场景的修复有效：未声明兄弟技能被过滤、验签读取异常 fail-closed、附属文件纯重命名可触发重验。

但交叉审查及补充复现又确认三项边界：

- R7：解析到包内其他目录的技能链接可能绕过 HMAC 覆盖。
- R8：技能加载的“先 resolve 检查、再按原路径读取”仍存在实际换链窗口。
- R9：包根链接循环可使热检测抛出 `RuntimeError`。

因此 **R4、R6 只能判定部分通过，R5 通过；v0.17.35 暂不能作为领域包信任链完全闭环版本**。本报告取代先前尚未定稿的通过结论。

## 3. 待修复问题

### R7【高】包内目录链接可造成“实际挂载目录不在 HMAC 载荷内”

位置：

- `server/packs.py::_resolve_in_pack` 只要求解析后的技能目录位于包根内。
- `server/packs.py::register_pack_skills` 按解析后的真实父目录注册实际技能。
- `server/packsign.py::_canonical_parts` 只遍历物理 `tools/**`、`skills/**` 和 `prompt.md`。

问题形态：

```text
pack/
  skills/x -> ../hidden       # POSIX 目录符号链接
  hidden/SKILL.md
```

`skills/x` 解析为 `pack/hidden`，仍在包根内，因此可以进入挂载集合；但 POSIX `Path.rglob` 默认不跟随目录符号链接，`hidden/SKILL.md` 不一定进入 `skills/**` 的 HMAC 载荷。结果可能是技能可加载而包仍显示 signed。

修复要求（优先严格布局方案）：

1. 技能目录解析后不仅要在包根内，还必须仍位于解析后的 `<pack>/skills/` 树内；指向 `hidden/`、`tools/` 等其他包内目录的链接同样拒绝。
2. 对叶子 `SKILL.md` 继续保留真实路径包含校验，并确保其父目录仍属于已接受的规范技能目录。
3. 如果允许目录链接，则必须把每个实际挂载目录及其文件纳入同一 HMAC；不能一边按真实目录加载、一边只签逻辑 `skills/**`。严格禁止目录链接是更小、更易验证的方案。
4. 签名集合、热检测集合、索引集合和加载集合必须再次保持同一。

必须新增测试：在支持目录符号链接的 POSIX/CI 环境创建上述 `skills/x -> ../hidden`，强制模式下不得出现“技能可加载且包 signed”；正常技能目录不受影响。

验证说明：当前 Windows 无目录符号链接创建权限，本项由代码路径和 POSIX 遍历语义确认，需用 Linux/CI 真实链接测试补足动态验收。

### R8【高】加载期检查与读取之间仍可换入包外链接

位置：`server/skills.py` 的 `_skill_entry_ok` 先对原路径 `resolve()` 检查，随后 `list_skills` / `load_skill` / `signature` 仍按原路径 `read_text()` 或遍历读取。

本机使用 Windows junction 在准入返回后立即替换目录，实测：

```text
toctou_swapped=True
outside_content_loaded=True
```

即检查时为包内 `good`，读取前换成指向包外的 junction，最终返回包外内容。当前“加载期再校验”没有真正闭合检查—使用间隔。

修复要求：

1. 不得以“再调用一次 resolve/read”宣称闭合；第二次检查与第三次读取仍有同类窗口。
2. 优先方案：验签/扫描时建立受控的不可变技能内容快照，索引和加载只使用该快照，内容变化经签名检测后整体替换。
3. 若继续实时读盘，需以单次打开的文件句柄为读取对象，并核验句柄最终路径/文件身份及包根归属；读取原路径前只做字符串检查不足以满足要求。
4. 索引、直查加载、frontmatter 别名兜底加载和签名遍历必须采用同一防护策略，不能只修 `load_skill` 的一个分支。

必须新增测试：在准入返回后、内容读取前换入包外 junction/symlink，所有读取入口均不得返回包外内容；正常技能与别名仍可加载。

### R9【中】包根链接循环可中断热检测

位置：`server/packs.py::packs_signature` 对每个包直接执行 `pack["dir"].resolve()`；`_rel_key` 目前只捕获 `ValueError`。

注入包根 `resolve()` 的 `RuntimeError: Symlink loop` 后：

```text
packs_signature_on_root_loop=raised Symlink loop
```

这会使每轮对话开始的热检测中断，而不是将异常包隔离并重扫。

修复要求：

1. 按包捕获路径解析/遍历的 `OSError` 和 `RuntimeError`，生成可比较的异常签名哨兵并触发强制重扫，不得中断其他包和当前对话。
2. 同步检查扫描、注册和验签路径对链接循环的处理，避免只修 `packs_signature` 后在下一入口再次抛出。
3. 异常签名应在故障恢复后发生变化，使包能经重扫自愈；不得缓存永久可信结果。

必须新增测试：包根自循环链接不使热检测或扫描上抛；健康包继续工作，链接恢复后可重新验签并恢复。
