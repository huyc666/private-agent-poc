### 2.1 确认为真的阻断项与整改

1. **PG 事务模型**：原先 PG 连接 `autocommit=True`，把 SQLite 多语句事务
   拆散。整改为 `psycopg_pool.ConnectionPool`，借出连接默认
   `autocommit=False`；`BEGIN IMMEDIATE` 在 PG 翻译为 `SELECT 1`，保留
   psycopg 已开启的隐式事务（`server/db.py:256`、`server/db.py:300`）。
2. **删除/栅栏竞态**：`mark_deleted` PG 分支改为单语句 upsert 并递增
   generation；`append_fenced` 与 `create_approval_fenced` 用
   `SELECT ... FOR UPDATE` 后写入（`server/sessions.py:328`、
   `server/sessions.py:243`、`server/approval.py:123`）。
3. **登录限流与定义级租约**：分别用
   `pg_advisory_xact_lock(hashtext(...))` 串行同一用户登录状态变更、
   同一 definition 的运行租约（`server/auth.py:280`、
   `server/schedulers.py:630`）。
4. **调度 claim**：到点与文件上传事件查询在 PG 附加
   `FOR UPDATE SKIP LOCKED`；触发留痕仍由唯一键 + `cursor.rowcount`
   保证 exactly-once（`server/schedulers.py:519`、
   `server/schedulers.py:565`、`server/schedulers.py:444`）。
5. **迁移原子性**：目标 PG 使用默认非 autocommit 连接，建表、复制、
   identity 重置与提交处于同一事务，异常回滚；目标非空 fail-fast，
   并按 500 行分批复制（`tools/migrate_db.py:83`、
   `tools/migrate_db.py:96`）。
6. **真实 PG 测试有效性**：AC5 改为独立 schema + 真实第二 Python 进程；
   AC7 查询 `information_schema.tables`；AC8 构造全部 12 张 state 表与
   2 张 usage 表源，验证 501 行分批复制、精度、序列重置和覆盖拒绝；
   AC11/AC12 使用独立 schema 并覆盖并发注册、租约、timer/event/definition
   claim；会话级 teardown fixture 清理 schema。

### 2.2 复审中新发现并已修复

- 文件上传事件 SQL 初次加行锁时误将隐式字符串拼接写成单元素 tuple，
  导致 SQLite 事件回归 8 处失败。已改为纯字符串隐式拼接，并用
  `py_compile` + 字节码常量检查确认 SQL 是 `str`。

### 2.3 2/2 确认为有效的设计点

- 14 表 DDL 与迁移清单完整，`run_records` 未遗漏（P2-6）。
- `usage.summary().by_run` 使用 `MAX(...)` 聚合，消除 PG 非法裸列；
- epoch/金额列为 `DOUBLE PRECISION`，避免 float4 精度退化（P2-3）。
- `session_locks.acquire` PG 单语句 `INSERT ... ON CONFLICT ... WHERE`
   原子接管。
- `register_session` 冲突幂等、审批最终状态条件更新、连接失败不泄漏
   URL 且不回退 SQLite。
- `setval(pg_get_serial_sequence(...), COALESCE(MAX(id),0)+1,false)`
   可避免显式导入 id 后的自增冲突。

## 4. 实机验证与边界

启动 Docker Desktop 后复用项目既有 `poc-postgres` 容器完成真实 PG 门控。
初跑出现 `5 failed, 7 passed`，根因是测试 schema 使用 PostgreSQL 保留
前缀 `pg_`（错误：`unacceptable schema name ... The prefix "pg_" is
reserved for system schemas.`）；唯一修复为把测试 schema 前缀改为
`pa_poc_test_`，复跑全绿。测试使用独立 schema，会话级 teardown fixture
关闭业务连接池并删除 schema，复测 `PA_POC_TEST_SCHEMAS=0`，未污染
`agent_poc` 基表。运行期间 C 盘可用空间从约 24.99GB 降至
24.93GB（净占用约 60MB）。
