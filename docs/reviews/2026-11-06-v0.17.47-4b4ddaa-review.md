## 2. Findings

### P2：N3 的畸形定义保护不完整，发现工具仍可被单文件拖垮

位置：

- `server/orchestration.py:194`：对可能同时含字符串和整数键的 YAML 对象执行 `sorted(set(definition) - _TOP_KEYS)`，Python 会抛 `TypeError`。
- `server/orchestration.py:289`、`:326`：将未限制类型的 `role` 直接用于 set membership；`role: []` 会抛“unhashable type”。
- `server/orchestration.py:332-334`：`aggregate.inputs` 只检查是 list，未检查元素是字符串；`inputs: [[]]` 会在 membership 判断中抛异常。
- `server/orchestration.py:307-309`：`fanout.from` 同样存在不可哈希值问题。
- `server/orchestration.py:1172-1192`：发现工具逐文件调用 `load_definition`，没有隔离校验异常。

独立复现结果：

```text
混合字符串/整数顶层键 -> TypeError: '<' not supported between instances of 'str' and 'int'
aggregate.role: []     -> TypeError: unhashable type: 'list'
aggregate.inputs: [[]] -> TypeError: unhashable type: 'list'
fanout.from: []        -> TypeError: unhashable type: 'list'
```

这些都是 `yaml.safe_load` 可接受的输入。`load_definition_text()` 只捕获 YAML 解析异常，未捕获 `validate_definition()` 异常；列举路径会把异常向上抛出，因此 N3 的“单个损坏或畸形定义不影响其他有效定义”仍未满足。

整改建议：

1. 让 `validate_definition()` 对任意 `safe_load` 结果保持 total function：排序未知键前转成稳定字符串表示；role/fanout.from 等先做标量/字符串类型判断，再做 membership；`aggregate.inputs` 对齐 steps.inputs 的字符串元素校验。
2. 在加载边界增加最后的结构化异常兜底，作为防御层，但不替代逐字段类型修复。
3. 将上述四类输入参数化为拒绝用例，并在每个用例中保留一个有效定义，断言列举不抛错且有效定义仍可见。
