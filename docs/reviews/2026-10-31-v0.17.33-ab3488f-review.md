## 2. 已闭环项（不要回退）

### 2.1 chat 锁内二次归属检查

`server/main.py` 已在进程内会话锁和跨进程租约内、首次 `sessions.append` 前再次调用 `_chat_session_denied`。拒绝发生在用户消息、assistant 消息和模型上下文写入之前，上一轮“两个用户同时以空 session_id 通过锁外检查”的窗口已关闭。

### 2.2 执行模式严格白名单

`server/custom_tools.py` 对非法 `CUSTOM_TOOLS_EXEC` 按沙箱模式处理；沙箱不可达返回 `sandbox-down`，不再落入 `auto → local`。真实模型未显式配置时仍默认沙箱 fail-closed。

### 2.3 上下文默认值

`server/config.py`、`.env.example` 和 README 的默认/示例值均为 `32768`，已与自带 vLLM `--max-model-len 32768` 对齐。128k 模型需显式配置 `CONTEXT_MAX_TOKENS=128000`。

### 2.4 知识库替换中断窗口

`tools/build_kb.py` 已改为 `shutil.copy2(db, bak)` 保留现役库，再单次 `os.replace(tmp, db)`。在替换点注入 `KeyboardInterrupt` 模拟中断，实测：

```text
db_exists=True
bak_exists=True
tmp_exists=False
active_docs=['a.md']
```

现役旧库保持完整，上一版“两步换名之间中断后只剩 bak”的问题已修复。

## 3. 待修复问题

### R1【P0】签名载荷与可加载资源范围不一致

**位置**

- `server/packs.py`：清单 tools/skills/prompt 经 `_resolve_in_pack` 后，可引用包内任意路径。
- `server/packsign.py::_canonical_parts`：签名只覆盖 `pack.yaml`、`tools/**`、`skills/**` 和固定 `prompt.md`。
- `sandbox/server.py`：包工具固定从 `/packs/<pack>/tools/<name>.py` 执行。

**问题**

清单可声明 `code/demo_tool.py` 等包内非标准路径。该文件能通过包目录包含检查，却不在签名载荷中；内容被篡改后，即使重新扫描，仍显示 `ok signed`。

实际复现：

```text
noncanonical_tool_initial=ok signed
noncanonical_tool_after_tamper=ok signed
```

同时，Agent 按清单路径提取工具元数据，沙箱却按固定 `tools/<name>.py` 执行，二者可能不是同一个文件，导致执行失败或执行同名不同文件。

**修复要求（优先采用规范路径方案）**

1. tools 限定为包内 `tools/<name>.py` 直接子文件，与沙箱现有执行契约一致；拒绝其他相对路径，不只是拒绝包外路径。
2. skills/prompt 如继续允许非标准包内路径，签名载荷必须覆盖**实际解析并加载的每一个资源**；更简单的方案是统一限定为规范 `skills/` 与 `prompt.md` 结构。
3. 签名、Agent 加载和沙箱执行必须指向同一个规范化路径。不得只增加文档警告或只改热重载检测。
4. 非标准路径应在解析阶段拒绝并告警；强制验签模式下不得出现“包外/未签名资源可执行但包仍 signed”的状态。

**必须新增的回归测试**

- 签名包声明 `code/demo_tool.py`：按选定契约拒绝，或篡改后必须变为 invalid/unavailable；绝不允许篡改后仍 `ok signed`。
- 清单声明路径与沙箱执行路径一致；同名不同路径文件不能被替代执行。
- 既有规范 `tools/<name>.py` 包正常加载，避免兼容性回归。

### R2【P0】领域包 Skills 仍可通过恢复 mtime 绕过重验

**位置**

- `server/skills.py::signature` 仍使用 `st_mtime_ns`。
- `server/packs.py::packs_signature` 只哈希 pack.yaml、已声明 tools 和 prompt，不包含 Skills。
- `server/agent.py` 只有签名变化才触发 `_rebuild_graph`，重建时才失效包缓存并重新验签。

**问题**

修改已签名包内 `SKILL.md` 并恢复原 mtime 后，Skills 与 packs 两组变更签名均不变，因此不会重建图、不会重新验签。

实际复现：

```text
skill_reload_signature_unchanged=True
```

**修复要求**

1. 将通用及领域包 Skills 的变更检测改为内容 SHA-256；可改 `skills.signature()`，或纳入 `packs_signature()`，但最终必须覆盖实际加载的全部 `SKILL.md`。
2. 文件读取失败应使用与当前 `_file_sig` 一致的异常签名兜底（如 `?`），保证异常状态变化会触发重扫，不得静默沿用可信状态。
3. 篡改后应触发 `_rebuild_graph`；强制验签模式下包必须变为 invalid/unavailable，并从可用技能索引移除。

**必须新增的回归测试**

- 修改已签名 `SKILL.md` 并恢复 mtime，签名必须变化。
- 热重载后重新验签失败，篡改技能不再可加载。
- 正常 Skills 创建/修改仍能热重载，既有行为不回退。

### R3【P1】技能叶子 `SKILL.md` 符号链接可逃逸包目录

**位置**

- `server/packs.py` 只对技能目录调用 `_resolve_in_pack`。
- 随后直接检查 `(p / "SKILL.md").is_file()`。
- `server/skills.py::load_skill` 读取时会跟随叶子符号链接。

**问题**

技能目录位于包内，但其中的 `SKILL.md` 自身若是指向包外的符号链接，现有目录包含检查无法阻止读取包外内容。

**修复要求**

1. 对 `(技能目录 / "SKILL.md").resolve()` 再执行包目录包含关系校验。
2. 叶子文件越界时拒绝该技能并告警；不得加入 `info["skills"]`。
3. 如技能目录内其他引用资源也参与加载，应使用同一真实路径边界策略。

**必须新增的回归测试**

- 包内技能目录 + 指向包外的 `SKILL.md` 链接必须被拒绝。
- 包内正常技能文件不受影响。
- 平台不支持创建符号链接时，可使用路径解析替身测试；支持的平台再补真实链接测试。
