## 3. 发现与整改

1. **PG 验收漂移（2/2）**：原真实 PG 用例复制 `by_task` SQL，没有调用
   `usage.summary()`，无法防止实现与验收 SQL 各自漂移。整改为在独立
   schema 中配置 `USAGE_BACKEND=postgres`，直接调用真实 `summary()` 断言
   `by_task`，并补 `session_id` 与 `days` 过滤断言
   （`tests/test_run_task_attribution.py:300`）。
2. **执行异常恢复（2/2）**：已有失败结果用例，但未显式覆盖 `execute()`
   抛异常后的 `current_task` 恢复。新增
   `test_ac3_execution_exception_restores_task_context`
   （`tests/test_run_task_attribution.py:227`）。
3. **术语与文档（2/2）**：`run_id` 原文案仍称“任务”，与新 `task_id`
   混淆；README 未记录 `by_task` 与 v0.19.0，PLAN 仍显示进行中。已统一
   “运行（run_id）/流程实例（task_id）”术语，并补 README v0.19.0、
   用量聚合说明与 PLAN 6.7 ✅。
4. **真实 summary 复测新发现**：调用真实 `summary()` 后，评审器暴露
   `by_session` 在 PostgreSQL 下仍选择非分组列 `user_id`，报
   `psycopg.errors.GroupingError`。根修为 `MAX(user_id) AS user_id`
   （`server/usage.py:452`），证明验收去漂移有效。
5. **测试辅助修复**：`_with_schema()` 原先遗漏，真实 PG 用例首轮出现
   `NameError: name '_with_schema' is not defined`；补齐后复跑通过。
