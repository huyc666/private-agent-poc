## 1. 复验结论

三轮整改的核心声明均通过代码逐行复核与独立行为复现：

- 删除会话 = 不可逆终局：tombstone 封禁跨连接生效（认证/开放模式同口径），删除后任何人（含原属主、含跨用户）不得以同 ID 接续，删除覆盖面（messages/tombstone/审批/租约）实测完整。
- 代际 fencing：流中途删除后 assistant 不落库且客户端收到明确 error 事件；`append_fenced`/`create_approval_fenced` 单事务栅栏实测拒绝旧代际写入；`FencedCheckpointer` 对已删线程的 checkpoint 写入抛 `SessionDeletedError`。
- XSS 防线：常规消毒矩阵 18 项（script/事件属性/`javascript:` 各形态/实体走私/data:text/html/iframe/svg/form 等）全部拦截，白名单元素与 `data:image/*` 正常保留；sanitize 端点 401/413/消毒行为正确。**但重复属性形态可绕过（见第 5 节 N1）**——单属性语义拦截完备，同名属性「危险在前、掩护在后」原样放行。
- Cookie + CSRF：登录发 HttpOnly/SameSite=Lax cookie，cookie 身份非 GET 请求缺 `X-Requested-With` 一律 403，Bearer 路径豁免，登出清 cookie。
- SSO 身份一致性：执行层 `current_role/current_department` 只读请求快照（monkeypatch 查表函数爆炸桩下仍返回快照值），SSO 部门头覆盖本地表、空头 fail-closed、Bearer 走本地表、并发请求互不串值、凭据优先级 SSO > Bearer > Cookie 各组合行为正确。

**本轮新发现 4 项（详见第 5 节）：1 项为消毒器可实测绕过的契约破坏（中，须修复），2 项为 FencedCheckpointer 契约违反（中低，潜伏，当前无实际影响），1 项为存量会话回填的授权放宽（低，一次性迁移窗口）。另有 2 项观察项。核心安全声明（删除终局、代际 fencing、SSO 身份一致性、Cookie/CSRF）全部通过，但「消毒输出即可信 HTML」与「包装后行为与被包装 saver 完全一致」两项声明当前不成立，建议修复后再将 v0.17.39 作为生产基线。**

## 5. 新发现

### N1【中·须修复】消毒器重复属性绕过：`/api/kb/sanitize` 契约破坏

`server/html_sanitize.py` L94/L101：`handle_starttag` 校验 URL 用 `dict(attrs).get(...)`（**同名属性取末次出现**），输出循环（L101-113）却**保留全部属性**。实测：

```python
sanitize_html('<a href="javascript:alert(1)" href="https://safe.example">x</a>')
# → '<a href="javascript:alert(1)" href="https://safe.example">x</a>'  原样放行
sanitize_html('<img src="javascript:alert(1)" src="data:image/png;base64,AA">')
# → 危险 src 原样保留
```

浏览器对重复属性 first-wins → `javascript:` 生效。反向顺序（safe 在前、危险在后）被正确剥壳——绕过只在「危险在前、掩护在后」时成立，正是攻击者会选择的形态。

当前缓解：唯一消费方 docx 渲染页 CSP `script-src 'self' 'nonce-…'`（无 unsafe-inline）使 `javascript:` URI 惰性；但 sanitize 端点是通用消毒通道，契约「输出即安全 HTML」已破——任何无 CSP 的复用上下文即成存储型 XSS。消毒器自身的正确性不得依赖消费方 CSP。

修复要求：输出循环对每个属性名只发首次出现（或校验与输出同取首个），并补重复属性回归用例。

### N2【中低·潜伏】FencedCheckpointer 写方法吞掉返回值

`server/agent.py`（v0.17.38 引入）：`aput/put` 只 `await self._inner.aput(...)` 不 return，违反 BaseCheckpointSaver 契约（`aput` 应返回 RunnableConfig）。实测 `fc.aput(...)` 返回 `None`。

影响面经交叉核实（langgraph 1.2.14）：主执行环 `_loop.py:1869` 忽略返回值，invoke/interrupt/resume/aget_state/**含 subgraph** 均不受影响（我实测迷你图全链路正确）；但 `pregel/main.py:2257/2313/2351/2573`（aupdate_state / `__copy__` fork / bulk update）用返回值构造 next_config——**time-travel/update_state 路径会静默拿到 None**（checkpoint 写入成功、config 丢失，patch_checkpoint_map 对 None 直通不炸）。server/ 现无此类调用，启用 time-travel 前必须修。`aput_writes/put_writes` 契约本就返回 None，无碍。

修复要求：`aput/put` 改为 `return await self._inner.aput(...)` / `return self._inner.put(...)`。

### N3【中低·潜伏】`_delegate_async` 把 async generator `alist` 包装成 coroutine

`server/agent.py` 末尾批量委托列表把 `"alist"` 放进 `_delegate_async`。langgraph 的 `alist` 是 async generator；经 `async def` 包装后调用返回 coroutine，`async for` 直接 `TypeError: 'async for' requires an object with __aiter__ method, got coroutine`（实测 `graph.aget_state_history()` 经包装后崩溃；交叉审查独立复现一致。正常 invoke/resume 不受影响——Pregel 仅在状态历史快照路径调 alist）。

当前 server/ 无任何 `alist`/`aget_state_history` 调用，**无现网影响**；但「包装后读写路径行为与被包装 saver 完全一致」的声明不成立，且未来使用时间回溯/历史 API 会立即踩中。

修复要求：`alist` 从 `_delegate_async` 列表移除，改为普通 `def alist(self, *a, **kw): return self._inner.alist(*a, **kw)`（生成器直传，不 await）；补一个 `aget_state_history` 经 FencedCheckpointer 的回归用例。

### N4【低】存量混合会话回填授权放宽（一次性迁移窗口）

`server/sessions.py:347-374 resolve_owner`：meta 缺失的存量会话按**最早一条 user 消息**回填 owner。若存量会话首条消息为 anonymous（开放模式遗留）、后续有真人发言，回填 owner=anonymous → `_can_access_session` 的 anonymous 宽恕使**任意登录用户可读写**该会话。旧口径 `owners ⊆ {username, anonymous}` 会拒绝第三方。仅影响 v0.17.37 前存量数据的一次性回填，方向是放宽授权。

建议：迁移/回填时扫描「owner=anonymous 但存在非 anonymous 发言」的会话并告警；或将宽恕口径收紧为「会话全部 user 消息均为 anonymous」才宽恕。

### O1【低·观察项】MOCK_LLM 分支不经 fencing 提交点校验

`agent.stream_reply` 的 `_fenced_off` 定义之后、`config.MOCK_LLM` 分支直接 yield mock 流并 return，三类提交点校验（轮前/审批创建/resume 前）不生效；mock 演示剧本走审批流时，在途删除后仍可能产出 pending 审批行。assistant 写回有 main.py 的 `append_fenced` 兜底（不落库），且 mock 为演示模式，风险可接受——建议在 mock 分支入口补一行 `fence_ok` 校验或在 spec 中明示该口径。

### O2【低·观察项】快照缺位回退在认证模式下对 anonymous 返回 admin（沿用旧契约）

`auth.py current_role`：快照 None 且 `current_user` 为 anonymous/空时认证模式也返回 "admin"。系 v0.17.9 以来的既有契约、非本轮引入；现网无触发路径（工具执行必在 stream_reply 内、审批 resolve 不执行工具、orchestration 是 chat 内工具），但属未来后台任务/新调用方的潜伏陷阱——新引入执行层入口时必须显式构造 Identity。
