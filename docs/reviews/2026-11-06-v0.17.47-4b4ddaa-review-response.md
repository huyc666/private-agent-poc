## P2 处置

报告指出的四类崩溃输入全部复现并修复，另发现并修复一处报告未点名的同源问题：

1. **`validate_definition` 对任意 `safe_load` 结果保持 total**（报告建议 1）：
   - 新增 `_unknown_fields` 助手：未知字段以 `key=repr` 安全排序、非字符串键
     `repr` 字符串化后拼接（四处调用点：顶层/角色/步骤/aggregate）。
   - 步骤 `role`、`fanout.from`、`aggregate.role` 成员判断前先做
     `isinstance(str)` 守卫（堵 unhashable 崩溃）。
   - `aggregate.inputs` 对齐 `steps.inputs` 的字符串元素校验。
2. **加载边界结构化兜底**（报告建议 2）：`load_definition_text` 对
   `validate_definition` 包 try/except，异常转「定义校验异常（类型名）」错误；
   作为最后防线，不替代逐字段修复。
3. **报告未点名的同源问题（自查发现）**：`load_definition_text` 错误分支原对
   畸形定义调用 `definition_hash`（`json.dumps sort_keys=True` 对混合类型键抛
   TypeError）——红跑暴露后修复：错误分支哈希置空（唯一消费方
   `run_orchestration` 在 `status == "ok"` 守卫后才读哈希，无影响）。
4. **用例**（报告建议 3）：五类畸形定义参数化为
   `test_p2_validate_definition_is_total`（mixed-keys / step-role / fanout-from /
   agg-role / agg-inputs），四类畸形 YAML 文件 + 一个有效定义写入
   `test_p2_malformed_yaml_files_do_not_crash_listing`，断言列举不抛错、
   畸形定义不可见、有效定义仍可见。
